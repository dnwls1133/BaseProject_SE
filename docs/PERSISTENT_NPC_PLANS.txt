# 지속 목표와 대면 상호작용 — 2026-10-21

## 이번 변경의 목적과 경계

이전 경제 버전의 상태 표시만으로 실제 상호작용을 설명하지 않는다. 이번에는 생활·경제가 활성화된 NPC의 목표 선택을 NpcPlanning.cpp로 옮기고 기존 이동·작업·전투 실행기를 연결했다. 공통 계획 계층이며 범용 GOAP/HTN 탐색기, 자유 자연어 대화, 모든 정치적 목표의 구현을 의미하지 않는다. 지도·세력·NPC·모델을 새로 복제하지 않고 기존 피난지–교역로를 첫 관찰 동선으로 사용한다. 공통 규칙은 다른 지역에도 적용한다.

소스에서 확인한 기존 문제는 가장 가까운 작업장 하나만 평가하는 방식, 도움 요청 단계에서 상대의 기존 행동까지 즉시 Meet으로 교체하는 방식, 목표를 나타내는 장기 상태와 실제 생활 단계가 분리되지 않은 점이다. 이것들이 사용자가 관찰한 모든 정체의 원인이라고 실행 검증한 것은 아니다.

## 목표와 단계

LifeState 안의 GoalPlan은 목표, 단계, 계획 ID, 시작 시각, 다음 재판단, 실패 장소와 회피 기한, 완료 작업 수, 초기 소지금, 대기 시간, 중단 이유와 결과를 보존한다.

목표: 식량 확보/식사, 회복, 생산 수입, 지역 공급, 주변 치료, 거점 경계, 새 정보 교환. 실행 단계: 대기, 방법 선택, 이동, 현장 실행, 상대/자리 대기, 위협 중단, 완료, 실패.

- 식량 확보 목표는 구매가 가능하면 창고를 선택하고, 돈이 부족하면 알려진 작업장에서 생산해 임금을 얻은 다음 다시 구매와 식사를 시도한다. 주변 주민에게 지원을 요청하는 경로도 있다.
- 생산 후보는 가장 가까운 한 곳이 아니라 고향/현재 지역/최근 전달받은 지역의 작업장을 평가한다. 실제 수요·투입 재고·임금·자리·이동 비용·적대 관계를 확인한다.
- 진행 중 작업을 매 판단마다 교체하지 않는다. 다음 단계의 선택은 현재 작업 완료 후 목표가 아직 미달인지 확인한 뒤 이루어진다.
- 전투·야생 위협·군사 명령은 실행에 우선하며 경제 맵의 생활 목표와 작업 상태는 유지한다. 위협 해소 후 이어가되 기존 작업 기한과 자원 조건을 다시 적용한다. 개인 간 약속은 위협에 따라 취소·환불하는 기존 규칙을 유지한다.
- 정체/실패한 장소는 지정 기간 피한다. 같은 거래의 출발/도착 장소도 회피 대상이다. 목적 달성은 자원·허기·피로·실제 작업/인계 결과로 판단한다.
- 생존 작업은 단순히 허기가 낮다는 이유로 매 틱 취소하지 않는다. 출정과 계약 운송 중에는 실제 소지 식량으로 허기를 해소한다.

## 동의와 물리적 인계

개인 도움 요청: 제안 시 요청자만 Meet으로 대기한다. 상대는 자원·신뢰·적대·긴급 욕구·다른 계약을 검토하고 수락한 후 기존 작업을 중단하고 합류한다. 요청자는 제시 조건을 검토하고, 필요가 사라지거나 대가가 부족하면 철회한다. 실제 거리와 시야 조건을 충족해야 약품/식량/정보가 인계된다. 다른 약속 참가자에게 중복 제안을 만들지 않는다.

지역 교역: 구매 지역에 실제로 존재하는 담당 NPC가 있어야 주문을 게시한다. 운송자와 구별되는 출고 담당자와 구매 담당자를 기록한다. 수락 때 양쪽 담당자의 신뢰·가용성 및 재고/금고 조건을 확인하고 예약한다. 계약 참가자는 다른 교역/도움 약속과 중복되지 않게 관리한다.

운송자가 장소에 가까워지면 출고/인수 담당자가 기존 행동을 잠시 멈추고 그 장소로 실제 이동한다. 운송자가 창고/시장에 도착해도 상대가 근처에 없거나 시야가 막히면 인계하지 않는다. 당사자와 만나 인계 시간을 채운 뒤 출고 또는 납품·정산한다. 현장 인계 결과는 개인 신뢰와 다음 거래 수락 여부에도 반영된다.

반송은 지역 창고로 반환하는 기존 규칙이다. 돌아가는 화물에 사망한 구매 담당자의 도착을 요구하지 않는다. 교전·사망·경로 또는 인계 대기 한도 초과 시 계약 취소/환불/반송/손실 규칙이 적용된다. 구매 주문 전달은 기존 거리 지연 추상화이며 전령 NPC를 새로 구현한 것은 아니다. 가격 제안/수락은 로컬 규칙이며 자유 협상 대화는 아니다.

## 코드와 데이터

- NpcPlanning.cpp: 목표 평가, 알려진 장소 판단, 단계 시작, 결과/실패 처리.
- SocietyEconomyInteraction.cpp: 거래 참가자의 중복 의무 검사, 지역 담당자 선택, 현장 이동과 접촉 판정.
- NpcLife.cpp: 목표 실행 연결, 동의 이후 공동 계획, 실제 작업·식사·이동.
- SocietyAI.cpp: 비전투 생활 실행 중 행동 표시를 무조건 Rest로 덮지 않도록 연결.
- WorldSociety.h: 공개 진단 타입과 메서드, 비공개 실행 함수. 사용자가 공개로 변경한 HasLife() 유지.
- level1.life의 planning 레코드: 허기 기준, 피로 기준, 목표 개인 식량, 인계 담당자 호출 거리, 재판단 세계 분, 실패 회피 세계 분, 목표 기한 세계 분, 현장 인계 대기 한도(실제 초).
- 현재 planning 값: 35 75 3 12 12 120 900 90. 기존 로더/파일 해시/배포 경로 재사용. 데이터 변경 후 재시작 필요.

## 저장·모니터·계측

저장 schema 7. life_plan 레코드와 경제 주문의 출고/인수 NPC ID를 추가했다. 대기 중인 제안과 수락된 양측 약속을 복원 검사에서 구분한다. 기존 world.save와 .bak는 변경하지 않는다. 구 저장 자동 변환은 없고 불일치 시 기존 자동 저장 중단 방침을 유지한다. 새 버전으로 수동 저장하기 전에 기존 파일을 따로 보관한다.

JSON의 behavior_model은 persistent_goals_v1, content_signature는 실제 로딩한 사회 콘텐츠 해시다. 모니터 상단에 지속 목표 v1이 없다면 이전 실행 파일/이전 상태 JSON일 수 있다. NPC plan 필드에는 목표/단계/계획 ID/대기 이유/시간/완료 단계/실패 장소/결과를, 계약에는 supplier/carrier/receiver를 표시한다. 게임 J 생활 목록도 동일 목표·단계와 대기 이유를 사용한다.

cpu_npc_goal_planning_ms, npc_plan_transition_count를 추가했다. npc_goal_selected와 npc_plan_stage 사건을 기존 society_change에 기록한다. 단계가 같은 동안 매 프레임 같은 전환 사건을 반복 출력하지 않는다. 실제 비용·FPS 개선을 측정한 것은 아니다.

## 사용자 확인 순서

1. 빌드 후 재시작하고 모니터 상단의 지속 목표 v1을 확인한다. 기존 저장 불일치 메시지와 자동 저장 중단 상태를 구분한다.
2. 피난지/교역로의 주민을 선택한다. 돈이 부족한 주민이 하나의 계획 ID 아래 작업→임금→식량 구매→식사로 이어지는지 확인한다. 수요·재료·자금·접근 가능한 일자리가 없으면 실패 사유를 확인한다.
3. 계약에서 출고 담당자/운송자/인수 담당자를 확인한다. 출고 담당자를 만나야 화물이 생기고, 인수 담당자를 만나야 재고·대금이 바뀌는지 확인한다.
4. 도움 제안 직후 상대의 기존 행동이 즉시 Meet으로 바뀌지 않고, 수락 후 합류하는지 확인한다.
5. 위협 해소 후 계획 재개, 실패 장소 회피, 대기 한도에 따른 반송과 환불을 확인한다.
6. 운송/약속 제안/자리 대기 도중 저장·복원하여 참여자와 자원이 중복되거나 사라지지 않는지 확인한다.

빌드·게임 실행·브라우저/서버 실행·테스트·화면 및 성능 검증은 수행하지 않았다. 사용자 실행에서 교역 정체가 남으면 plan.blocked_reason, waiting_seconds, 계약 참여자 위치, stalled_seconds를 함께 비교해야 한다. 다음 확장 대상은 실제 이동 위험을 공유하는 호위 요청, 다단계 생산 의뢰, 세력 차원의 장기 목표이며 이번 변경에 모두 포함되었다고 설명하지 않는다.

# 외부 콘텐츠 제작 안내

2026-09-22. 첫 레벨 콘텐츠는 UTF-8 텍스트 파일을 로딩한다. 새 레벨을 만들 때 기존 C++ 클래스나 모델 생성 코드를 복사하지 않는다. 이 문서와 바꿀 데이터 파일만 먼저 읽고, 공통 기능의 부족이 있을 때만 해당 로더/동작을 확장한다.

## 먼저 찾을 파일

| 변경할 내용 | 파일 |
|---|---|
| 실행할 레벨 선택 | SimpleGame/Data/world.catalog |
| 맵 크기·시작점·지형·길·구역·색·배치·적 구성·목표 | SimpleGame/Data/Levels/level1.world |
| 적 이름·모델·체력·공격·방어·경험치·이동/공격 속도 | SimpleGame/Data/enemies.actors |
| 소품 모델·역할·바닥 패스·충돌·가림 처리 | SimpleGame/Data/props.actors |
| 성장·공격·회복·교환 규칙 | SimpleGame/Data/rpg.rules |
| 모델 목록·공통 애니메이션 유형 | SimpleGame/Data/models.catalog |
| 플레이어·몬스터·소품의 형상·색·재질·관절 | SimpleGame/Data/Models/<이름>.model |
| 튜토리얼 기존 맵·대사 | SimpleGame/Data/village.level, dialogue.ko.txt |

파일은 JSON이 아니라 줄 단위의 버전 있는 외부 텍스트 형식이다. 별도 라이브러리 없이 공통 로더로 읽으며, 한 레코드씩 작게 수정할 수 있도록 했다. 확장자가 다르더라도 아래 문법은 같다. 입력·충돌·전투 알고리즘·Scene Graph·애니메이션 계산·GLSL·공통 UI 구성은 실행 코드에 남는다. 튜토리얼 VillageArt의 별도 도형 표현을 이번에 외부화한 것은 아니다.

## 공통 문법

- UTF-8. 첫 유효 행은 `version 1`. 빈 줄과 `#` 주석을 허용한다.
- 행 하나가 레코드 하나다. 값은 공백으로 구분한다. 공백이 포함된 이름·문장은 큰따옴표로 감싼다.
- 참조 경로는 Data 폴더 기준 상대 경로이며 `/`를 사용한다. 상위 경로(`..`)와 절대 경로는 허용하지 않는다.
- 누락·중복 ID·알 수 없는 레코드·수치 범위·참조 대상 등을 검사한다. 행 구문 오류는 파일명과 행 번호, 참조 오류는 관련 파일과 ID를 콘솔에 표시한다.
- 실패 시 임의의 기본 맵으로 대체하지 않는다. 최초 진입 실패는 튜토리얼에 남고, 재생성 실패는 기존 월드를 유지한다.

## 새 레벨을 추가하는 순서

1. `Data/Levels/`에 새 `.world` 파일을 만든다. 기존 파일을 데이터 템플릿으로 사용하고, 적/소품/모델 카탈로그는 재사용한다.
2. 맵 크기, 시작점, 구역 이름·색상, 지형·길, 랜드마크·적 구성과 목표를 수정한다.
3. 같은 소품을 재사용할 때 모델 파일을 복제하지 않고 `place` 또는 `scatter`의 ID·위치·크기·좌우 방향만 바꾼다.
4. 기존 적의 수치나 모델만 다른 적은 `enemies.actors`에 새 ID로 정의하고 구역의 적 목록에서 참조한다. 새로운 AI 동작이 필요할 때만 공통 전투 코드를 확장한다.
5. `world.catalog`의 `entry`를 새 파일로 바꾸면 다음 프로그램 시작 시 같은 `LevelOne` 실행 코드로 진입한다. `LevelOne::Start(root, relativeFile)`도 같은 로더를 사용한다. `LevelTwo.cpp` 같은 복제 클래스를 추가하지 않는다.
6. 이번 변경을 처음 적용할 때는 사용자가 새 C++ 로더를 빌드해야 한다. 이후 지원하는 데이터 범위의 수정은 소스 재컴파일 없이 배포 Data 파일을 교체해 반영할 수 있다.

현재 여러 레벨을 잇는 포털이나 월드 스트리밍은 구현하지 않았다. 로더 재사용과 시작 레벨 선택을 지원한다는 의미다.

## .world 레코드

```
size 가로 세로
start 시작X 시작Y
title "레벨 이름"
introduction "입장 안내"
enemies enemies.actors
props props.actors
rules rpg.rules
goal 목표레벨 아이템획득수 배분포인트수
region ID 스타일 "표시명" 중심X 중심Y 반경X 반경Y 바닥R G B 물R G B 안개R G B A 적수 적ID...
patch 타일 중심X 중심Y 반경X 반경Y
road 시작X 시작Y 끝X 끝Y 반폭
place 소품ID X Y 크기 좌우방향
scatter 소품ID 중심X 중심Y 반경X 반경Y 최대개수 최소간격
```

- 맵은 24~160타일/축을 지원한다. 현재 첫 레벨은 80×64다. 좌표는 월드 타일 단위다. 시작점·구역 중심·랜드마크는 가장자리에서 두 타일 이상 안쪽에 둔다.
- 바닥 전체가 이동 가능한 황무지로 시작한다. `patch`는 타원형 영역을 덧칠한다. 타일 0=이동 불가 지형, 1=석재, 2=얕은 물, 3=초지/황무지, 4=흙길이다.
- `road`는 선분을 따라 길을 덧칠한다. 선분을 이어 굽은 길을 만들 수 있다. 길 밖의 초지 역시 이동 가능하다. 길이 물을 통과하는 부분은 건널목으로 칠해진다.
- 스타일 0=성소, 1=순례길, 2=매장지, 3=습지, 4=대성당, 5=균사 지대. 스타일은 기존 문양·포자 표현을 선택한다. 표시명과 바닥·물·안개 색은 별도 값이므로 구역 이름을 늘릴 때 enum을 추가할 필요가 없다.
- 구역은 밀폐된 방이 아니라 이름·색·적 배치의 영향권이다. 반경은 적 배치 영역이며 물리적 경계를 만들지 않는다. 가장 가까운 중심의 표시명과 팔레트를 사용한다.
- `place`의 크기는 0.5~1.3, 좌우방향은 1 또는 -1이다. 소품의 blocking 플래그가 켜져 있으면 해당 타일에 충돌을 만든다. 현재 충돌은 타일 하나이며 실제 메시 외곽 충돌은 아니다.
- `scatter`는 도로·석재·물과 시작점 주변을 피하고, 기존 배치와 간격을 유지한다. 지정 수량은 상한이며 공간이 부족하면 줄어든다. 배치 기록 자체를 재작성하지 않고 생성 시드를 사용한다.
- 생성 후 시작점에서 도달 가능한 바닥을 조사한다. 고립된 바닥은 이동 불가로 전환하여 접근 불가한 플레이 영역을 남기지 않는다. 제단 접근성을 확인하며, 적은 도달 가능한 목록에서 배치한다.
- 최소 하나의 고정 `shrine` 소품이 필요하다. 성장 목표와 소지품은 기존처럼 같은 실행 중 누적되고, 재실행 간 세이브는 아직 없다.

## 적·소품·규칙

각 파일 첫 주석에 값의 순서를 기록했다. 이름을 인덱스로 참조하지 않고 ID를 사용한다.

- 적: `enemy ID "이름" 모델 체력 공격 방어 경험치 이동속도 준비시간 대기시간 공격범위 보행속도계수 그림자폭 체력바높이 추적거리`
- 소품: `prop ID 모델 역할 바닥표시 충돌 큰장식 그림자폭`. 플래그는 0/1. 역할은 static, shrine, brazier, fungal 중 하나이며 각각 기본 장식·휴식 제단·불꽃/빛·균사 빛을 연결한다. 바닥표시 소품에는 충돌을 설정하지 않는다.
- 성장: `growth 최대레벨 경험치기본 경험치증가 레벨업포인트 체력기본 레벨체력 생명체력 공격기본 레벨공격 힘공격 방어기본 저항방어 회복량`
- 전투: `combat 이동속도 공격중속도 공격범위 공격시간 재사용시간 판정시점 무적시간 최소회복약 교환비용 회복약드롭주기`
- 능력치 UI와 회복·교환 문구도 읽은 수치로 표시한다. 기존 게임 알고리즘을 데이터가 실행하는 스크립트 시스템은 아니다.

## 모델 파일과 캐시

`models.catalog`는 `model 이름 rig 상대파일`을 나열한다. 첫 19개 기본 이름/순서는 기존 엔진 ID와 호환되도록 유지한다. 새 모델은 끝에 추가하고 적·소품에서 이름으로 참조할 수 있다. rig는 static, pilgrim, creature 중 하나로 기존 관절 계산을 선택한다.

각 `.model`은 아래 도형을 그리는 순서대로 기록한다. 기존 모델 19종의 도형 486개를 이 형식으로 옮겼다. 큰 모델 파일 전체를 매번 다시 작성하지 말고 해당 부위의 행만 수정한다.

```
triangle 재질 관절 R G B A x1 y1 x2 y2 x3 y3
quad 재질 관절 R G B A x1 y1 x2 y2 x3 y3 x4 y4
ellipse 0 관절 R G B A 중심X 중심Y 반경X 반경Y
segment 재질 관절 R G B A 시작X 시작Y 끝X 끝Y 반폭
```

- 좌표는 발밑 원점 기준 화면 픽셀이다. 위쪽이 음수 Y다. RGB는 0~3, 알파는 0~1이다.
- 재질: 0=기본, 1=석재, 2=흙, 3=목재, 4=천, 5=포장석, 9=감염 조직. 타원은 현재 기본 재질만 지원한다.
- 관절: 0=몸통, 1/2=다리, 3/4=팔, 5=망토, 6=머리/성장 조직. 새 rig의 움직임이 필요하면 공통 애니메이션을 확장한다.
- 모델별 최대 정점 수 60,000. 현재 로더의 생성 후 좌표 범위는 X ±150, Y -160~60이다. 기존 화면 크기에 맞는 모델을 유지하고 큰 새 모델을 도입할 때는 Actor 렌더 경계·그림자·가림도 함께 조정한다.
- 캐시 파일은 기존 `Data/Cache/level1_models.bin`, 형식 버전은 4다. 카탈로그와 모델 파일의 내용 해시가 다르면 자동으로 다시 생성한다. **일반 모델 데이터 수정에는 C++ CacheVersion 변경이 필요 없다.** 캐시 구조·정점 생성 방식이 바뀔 때만 버전을 올린다.
- 캐시가 유효하면 파일 내용 해시 확인 후 저장된 정점을 불러와 도형 생성 과정을 생략한다. 원본 모델 파일은 배포에도 필요하다. 캐시는 콘텐츠 원본이나 플레이 세이브가 아니다.

## 기존 나무 재사용

`dead_tree`(마른 고목)와 `blighted_tree`(감염목)는 props.actors에 등록되어 있다. 새 레벨에서는 .world의 place/scatter에 이 ID를 사용한다. 모델은 DeadTree.model과 BlightedTree.model이며 새 C++ 모델 생성 코드나 별도 나무 클래스를 만들 필요가 없다. 둘 다 정적 모델이며 기존 큰 소품의 가림·그림자·타일 충돌을 사용한다. 작은 숲은 최소 4타일 간격을 기준으로 조정하고 길과 전투 공간의 시야를 확보한다.

## 적용·확인 범위

Visual Studio의 `CopyGameContent`가 원본 `SimpleGame/Data`의 하위 폴더를 빌드 출력 `Data`로 복사한다. `Cache`는 복사에서 제외한다. 실행 파일이 읽는 Data와 편집한 원본 Data를 구분한다.

- 월드·적·소품·성장 파일: 실행이 사용하는 Data에 반영한 뒤 제단에서 R로 다시 읽는다. 오류가 있으면 기존 월드가 유지된다.
- 모델·models.catalog·world.catalog: Data에 반영한 뒤 프로그램을 재시작한다. 모델 변경 시 캐시 내용 해시를 자동 비교한다.
- 배포 파일 복사는 다음 사용자 빌드 시 자동 수행한다. 단순 데이터 수정은 사용자가 실행 Data 폴더로 직접 복사해도 된다.

빌드·실행·테스트·화면 확인은 수행하지 않았다. 사용자가 직접 길 밖 이동, 폐허/수변의 충돌, 적 배치·전투·성장, 제단 재로딩, 모델 캐시 상태를 확인한다. 기존 시각 품질을 기준으로 만들었으나 야외 지형과 데이터 로더 변경 후 화면은 아직 확인 전이다.

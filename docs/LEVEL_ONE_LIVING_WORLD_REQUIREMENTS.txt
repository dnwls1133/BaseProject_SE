# LevelOne 자율 전투·마을 정치·경제 요구사항

작성: 2026-11-11. 상태: 요구사항 초안. 이번 작업에서 구현한 기능은 첫 레벨 직접 시작뿐이다.
아래 전투·정치·경제·모션 항목은 기존 기반 위에 추가할 요구사항이며 완료 보고가 아니다.
기존 세계관과 GameWorldConcept.md의 비결정형 미래 원칙을 따른다.

## 1. 확정 방향과 현재 맵

- 플레이어가 관여하지 않아도 감염체와 NPC가 싸우고, 마을이 거래·경쟁·협상·암투를 수행한다.
- 말풍선이나 상태 문구만 바뀌는 연출로 상호작용을 대신하지 않는다. 이동, 대상 접촉, 비용 지출, 피해와 후속 행동이 연결되어야 한다.
- 256×256 맵과 정화 기사단·군체의 두 세력을 유지한다. 마을 정치 때문에 새 세력을 자동으로 추가하지 않는다.
- 기사단 피난 마을(refuge), 보급 교역촌(pilgrimage), 정화 요새(graves), 정화 수도원(cathedral), 군체 심장림(growth)의 다섯 거점을 사용한다.
- 현재 초기 사회 NPC는 거점당 20명, 총 100명(기사단 80명, 군체 20개체)이다. 야외 몬스터 100마리는 별도 개체군이다.
- 군체의 핵심 목표는 감염 확산이다. 사람 마을의 화폐 거래와 군체의 생물학적 자원 획득을 구분한다.
- 확정된 소울류 다크 판타지·코스믹 호러를 유지한다. 정치 갈등은 생존, 성혈 의존, 감염자 처우의 이해 충돌에서 나온다.

## 2. 소스에서 확인한 기반과 보완 지점

실행 관찰 결과가 아니라 현재 코드와 데이터의 확인 내용이다.

| 영역 | 이미 존재하는 기반 | 이번 요구사항의 보완 대상 |
|---|---|---|
| 시작 | Game::Load 끝에서 LevelOne 진입을 시도함 | 튜토리얼 맵·대사 로딩을 거치지 않는 직접 시작, 실패 시 오류 보고 |
| 군체 전쟁 | SocietyConflictCombat의 7종 공격 패턴, 오염 확산과 소각, Damage 호출 | 역할별 협동, 보급과 목표 선택, 야외 Enemy와 사회 NPC의 일관된 교전 |
| 생활 판단 | NpcPlanning의 지속 목표와 NpcLife의 현장 실행 | 위험·수요·관계가 달라질 때 방법과 다음 행동이 달라지는 계획 |
| 경제 | 실제 재고·금고·소지금, 생산·예약·운송·정산·손실 | 지역별 이해관계, 호위·강탈·봉쇄·암투와 물류 결과 연결 |
| 정보 | 전령 이동과 근거리 대면 전달 | 비밀·증거·거짓 정보의 출처와 전달 경로, 정보 수신 후 판단 변화 |
| 정치 | 세력 관계·전쟁·일부 서사 기반 | 같은 기사단 안의 마을별 관계와 이해관계. 전장 모드의 소속 비교만으로는 표현 부족 |
| 모션 | 리소스 스킨과 클립 재생, Idle/Walk/Run/Attack/Hit/Death/Jump 선택 | 공격 패턴별 구분, 전투 단계 동기화, 작업·운반·거래·치료 전용 표현 |

특히 현재 전장 코드에는 같은 세력이면 공격 후보에서 제외하는 경로가 있다.
마을 암투를 추가하려면 세력 소속, 거주 마을, 현재 임무, 개인 관계, 교전 허가를 별도로 평가해야 한다.
현재 모든 행동 모션을 가진 것으로 가정하지 않는다. ResourceLibrary3D는 일부 생활 activity에도 Attack을 선택한다.

## 3. 항목별 기능 요구사항

### START-01 — LevelOne 직접 시작

- SimpleGame.cpp는 Game::LoadFirstLevel("Data/")를 호출한다.
- Game은 기존 LevelOne::Start와 Data/world.catalog의 entry를 재사용한다.
- 시작할 때 village.level, dialogue.ko.txt와 튜토리얼 Scene을 로딩하지 않는다.
- 첫 월드 로딩 실패 시 성공으로 처리하거나 빈 튜토리얼로 넘어가지 않는다. 기존 콘텐츠 오류를 보고하고 시작을 중단한다.
- 기존 저장 복원 정책은 LevelOne::Start를 따른다. 저장을 임의로 지우거나 매 실행 새 세계로 초기화하지 않는다.

### COMBAT-01 — 감염체와 NPC의 실제 상호 피해

- 군체 사회 NPC, 야외 감염 몬스터, 기사단 주민·병사를 구분해 대상을 선택한다.
- 양쪽 모두 실제 피해를 줄 수 있고 체력·경직·부상·사망에 동일한 결과 규칙을 적용한다.
- 전투 기록에는 공격 시도, 명중, 방어·무적에 따른 피해 차단, 최종 피해를 구분한다.
- 죽은 대상·제거된 Actor·사라진 임무를 계속 공격하지 않는다. 반격은 인지·공격 가능 조건을 만족할 때 수행한다.
- 주민은 전투력과 공포에 따라 도주·신고·부상자 지원을 선택하고, 경비는 위협을 확인해 대응한다.
- 확인 기준: 플레이어가 공격하지 않아도 적대 양측의 체력과 피해 원인이 기록되고 사망/도주 결과가 후속 목표에 반영된다.

### COMBAT-02 — 서로 다른 전술과 협동

- 기사단은 방어선 유지, 측면 이동, 부상자 엄호, 화염 정화, 물자 호송을 역할에 따라 평가한다.
- 군체는 근접 압박, 도약, 원거리 포자, 군락 보호, 약한 보급로 공격을 개체 특성에 따라 평가한다.
- 준비 → 공격 실행 → 유효 타격 구간 → 회복 순서를 공유하며 준비 중 목표 지점을 예고한다.
- 체력·수적 불리·지형·아군 위치·보급에 따라 공격, 엄호, 우회, 후퇴를 선택한다.
- 공격을 순서대로 무한 반복하는 패턴표만으로 전술을 구현하지 않는다. 선택 근거와 취소 사유를 남긴다.
- 확인 기준: 같은 부대도 보급이 끊기거나 전력이 줄면 기존 공격을 계속하지 않고 전술을 바꾼다.

### INFECTION-01 — 감염과 정화가 지형과 행동에 영향

- 기존 오염 격자를 재사용해 군체 확산이 이동 위험·작업 안전·교역로 선택에 영향을 주도록 한다.
- 기사단 정화에는 현장 접근, 준비 시간과 연료/자재 비용이 필요하다. 비용은 기존 재고 원본에서 차감한다.
- 군체는 위협받는 확산 거점과 연결 경로를 지키거나 다른 경로로 확산한다.
- 정화·확산 효과는 실제 격자 상태와 함께 갱신하며 불꽃만 보여주고 상태가 변하지 않는 처리를 금지한다.
- 주민 감염 시 즉시 변이/잠복/치료 가능 여부는 Q2에서 결정한다. 사용자 결정 전 대규모 강제 변이 규칙을 확정하지 않는다.

### ECON-01 — 마을별 생산과 생존 의존

- 기존 식량·약품·자재를 공통 원본으로 사용하고 마을별 생산 특화와 목표 재고를 설정한다.
- 생산에는 노동자, 접근 가능한 시설, 시간, 실제 투입 재료와 임금이 필요하다.
- 식사·치료·군사 보급·시설 수리의 소비가 생산과 교역 수요를 만든다.
- 부족 지역은 구매, 대체 공급처 탐색, 배급 조정, 지원 요청을 비용·관계에 따라 비교한다.
- 군체는 화폐 시장의 상인이 되지 않으며, 제안 단계의 생체 자원은 기존 사람 경제 재고와 중복 생성하지 않는다.
- 확인 기준: 생산 중단이나 납품 실패가 목적지 부족과 작업/전투 판단에 영향을 준다.

### ECON-02 — 실제 호송과 교역로 분쟁

- 기존 계약의 예약 → 출고 → 이동 → 대면 인수 → 입고·정산을 유지한다.
- 위험한 계약은 호위 고용, 운송 연기, 우회, 수송 거절 중 하나를 선택할 수 있다.
- 호위는 같은 임무·화물·도착지를 참조해 운송자와 함께 이동하며 위협을 만나면 대응한다.
- 강탈·운송자 사망 때 화물의 지상 잔존, 회수 또는 손실 중 Q5의 규칙을 적용한다. 공격만으로 양쪽 창고에 물자가 동시에 생겨서는 안 된다.
- 확인 기준: 교역로 습격 → 실제 납품 손실 → 목적지 재고 부족 → 가격/배급/지원 판단 변화가 같은 원인 ID로 이어진다.

### ECON-03 — 가격과 거래 조건의 변화

- 가격은 재고 부족, 운송 위험, 생산 비용과 마을 관계를 반영한다. 기존 가격 산정·계약 원본부터 확장한다.
- 가격에는 하한·상한과 변경 주기를 두고 임의의 매 프레임 변동을 피한다.
- 계약 수락 시 가격과 예치금을 확정한다. 도중 가격 변화로 기존 계약의 돈이 중복 생성되지 않는다.
- 봉쇄·우선 공급·일시 거래 거절은 부족분, 정치적 목적, 자국 피해를 함께 평가한다.

### POL-01 — 마을별 관계와 이해관계

- 세력 소속과 별도로 마을 간 신뢰, 의존, 원한, 거래 제한을 관리한다.
- 같은 기사단 소속이라도 배급 우선권, 호위 인력, 정화 비용, 감염자 수용을 놓고 충돌할 수 있다.
- 공개 전쟁 허용 범위는 Q1로 결정한다. 기본 제안은 내부 암투와 경제적 압박을 허용하고 무차별 내전은 제한하는 것이다.
- 개인 관계는 마을 관계와 분리한다. 적대 마을 출신이라는 이유만으로 모든 NPC의 개인 기억을 덮어쓰지 않는다.
- 확인 기준: 같은 기사단의 두 마을이 군체 방어에는 협력하면서도 보급 배분에서는 다른 선택을 한다.

### POL-02 — 비용과 발각 가능성이 있는 암투

- 최초 후보는 보급 은닉, 창고 절도, 전달 문서 조작, 허위 소문, 상대 마을 지원 거절이다. 사용할 후보는 Q3에서 선택한다.
- 암투는 의뢰자, 실행자, 대상, 목적, 실제 비용, 실행 단계, 알려진 증거, 목격자를 가진다.
- 물리적 개입은 실행자가 현장에 도착해야 성립한다. 정보를 조작하려면 문서나 수신자와 접촉해야 한다.
- 수행자는 발각 위험, 보상, 충성심, 개인 관계에 따라 수락·거절·폭로할 수 있다.
- 성공/실패/중단/발각 후에는 재고·지식·관계 또는 시설 상태가 실제로 달라진다.
- 새로운 사건을 일정 시간마다 무조건 발생시키지 않는다. 목적과 조건이 사라지면 취소하거나 재계획한다.

### INFO-01 — 소문·증거·보고의 물리적 전달

- 세계의 실제 사실과 NPC가 믿는 정보를 별도로 보관한다.
- 비밀 정보에는 사건 ID, 발신자, 최초 출처, 발생/습득 시각, 신뢰도와 검증 여부를 둔다.
- 기존 전령과 NewsContact를 통해 이동·대면한 뒤 전달한다. 다른 마을에 생성 즉시 전파하지 않는다.
- 거짓 소문만으로 상대의 실제 죄를 확정하지 않는다. 수신자는 성향·관계·출처·증거를 보고 조사·보류·대응을 선택한다.
- 군체 공유 지식의 전달 범위와 속도는 Q2에서 정한다. 인간 전령 규칙을 이유 없이 전역 순간 통신으로 바꾸지 않는다.

### POL-03 — 지도자와 주민의 다른 판단

- 지도자는 마을의 방어·경제·지지 상황에 근거해 목표를 정하고, 실제 수행 NPC에게 임무를 전달한다.
- 주민은 굶주림·피로·부상·가족/개인 관계·위험을 고려해 명령 수락, 지연, 거부를 선택한다.
- 지도자의 사망·이탈은 미완료 임무의 재지정과 권한 공백으로 이어진다. 승계와 주민 증원 방식은 Q5에서 결정한다.
- 지도자 한 명의 전역 상태값 변경만으로 모든 주민의 행동을 즉시 동기화하지 않는다.

### PLAN-01 — 반복 이동을 줄이는 지속 목표

- 기존 GoalPlan에 전투·호위·정치 목적과 취소/실패 원인을 연결한다.
- 현장 조건이 맞지 않으면 같은 실패 장소로 매번 돌아가지 않고 비용과 알려진 대안을 평가한다.
- 장기 목표는 유지하되 위협 발생 시 중단하고, 위협이 사라지면 유효한 단계에서 재개한다.
- 이전 행동의 결과를 무시하는 작업 → 거래 → 전투 순환을 금지한다.

## 4. 모션·효과 요구사항

아래는 필요한 표현 목록이다. 현재 Resource 원본이 해당 클립을 모두 제공하는 것은 아니다.
코드에서 이미 있는 Attack을 재사용하는 것과 전용 모션 확보를 구분한다.

| 모션 ID | 필요한 표현 | 판정·상태와의 연결 |
|---|---|---|
| MOT-01 | 보행·달리기·방향 전환·무기 준비 | 실제 이동 거리로 발 움직임을 맞추고 정지 상태 발 미끄러짐을 줄임 |
| MOT-02 | 횡베기·찌르기·화염 준비/방사/회수 | 공격 스타일과 시간 단계에 맞는 클립 선택, 유효 구간에만 피해 |
| MOT-03 | 군체 도약·포자 발사·강타·포낭 살포 | 준비 방향/착지점/발사 순간을 실제 공격 목표와 맞춤 |
| MOT-04 | 피격·경직·방어·후퇴·사망 | 피격 중 공격 중단 가능 여부 명시, 사망 후 중복 타격 방지 |
| MOT-05 | 화물 들기·운반·내려놓기·인계 | 실제 보유 화물과 소켓 연결, 완료 시점에만 재고 이전 |
| MOT-06 | 채집·제작·치료·시설 수리·정화 | 작업 누적 시간과 도구·효과 표시, 대상 소멸 시 중단 |
| MOT-07 | 대면 보고·문서 전달·주변 살피기·은밀한 접근 | 수신자 접근과 실행 단계 표시. 비밀 임무를 모든 NPC 머리 위에 공개하지 않음 |
| FX-01 | 공격 예고·접촉 섬광·포자 투사체·화염·발자국 | 실제 명중/빗나감과 구분, 이펙트만으로 피해를 적용하지 않음 |

- ResourceLibrary3D의 클립 선택과 프리팹 메타데이터를 확장하고 기존 스킨/GPU 본 팔레트를 재사용한다.
- 전용 클립이 없으면 누락을 명시한다. 허용한 대체 클립이나 절차적 보정의 범위는 Q4에서 정한다.
- 작업마다 새 메시를 로딩하지 않는다. 도구·화물은 기존 리소스와 Actor/Scene 수명 규칙을 사용한다.
- 화염·포자·물결은 기존 시간 기반 셰이더를 재사용하며 효과 개수와 그림자 비용에 예산을 둔다.

채택 시 ContentData의 버전 있는 줄 단위 텍스트, ID·참조·범위 검사와 콘텐츠 해시에 연결한다.
JSON은 관측용 메시지 형식으로 사용하며 원본 콘텐츠 형식을 임의로 JSON으로 바꾸지 않는다.

## 6. 관측·저장·성능 요구사항

- 논리 상태 변경은 원인 ID, 행위자/대상 ID, 마을 ID, 세계 시각, 변경 전후 값으로 추적한다.
- 모니터에는 실제 세계 상태와 NPC가 믿는 정보를 구별해 표시한다. 플레이어 게임 UI의 정보 공개 범위는 별도다.
- 마을별 재고·가격·금고·생산·교역 손실·치안·공포·불만·신뢰와 사유를 표시한다.
- NPC별 목표·단계·대상·교전 의도·실제 피해·화물·현재 모션·실패 이유를 연결한다.
- 화면 밖 갱신도 사망·소비·계약·정보 규칙을 공유한다. 근거리와 원거리 판정을 중복 적용하지 않는다.
- Actor 업데이트와 렌더는 Scene을 유지한다. 판단은 분산 주기·주변 후보·메시지 예산을 사용하며 전수 쌍 비교를 추가하지 않는다.
- 전투, 정치 판단, 전령 접촉, 경제 정산, 애니메이션 갱신의 CPU 시간·건수·대기량을 기존 JSONL에 기록한다.
- 60 FPS/16.67ms는 목표이며 실행 확인 전 달성했다고 보고하지 않는다.
- 신규 영속 상태 도입 때 저장 스키마를 조정한다. 이번 문서 작성만으로 현행 스키마 9를 바꾸지 않는다.
- 기존 저장 불일치 시 파일 보존과 자동 저장 중단 정책을 지킨다. 모델 캐시 버전은 일반 콘텐츠 추가로 올리지 않는다.

## 7. 단계별 완료 판단

1. 직접 시작: LevelOne의 world.catalog를 읽고 진입한다. 튜토리얼 파일 없이도 이 경로를 사용할 수 있어야 한다.
2. 전투: 플레이어 개입 없이 군체/야외 감염체와 기사단이 서로 피해를 주며, 도주·지원·사망 결과와 모션 시각이 일치한다.
3. 물류: 한 교역로 습격이 실제 화물 손실과 목적지 부족을 만들고 NPC가 호위·우회·새 구매처를 선택한다.
4. 정치: 한 마을의 보급 은닉/허위 보고가 현장 행동으로 실행되고 정보 전달 전후 다른 마을의 판단이 달라진다.
5. 통합: 같은 시작 조건에서 호송 성공/실패, 증거 전달 유무가 다른 후속 결정을 만든다. 사건 순서와 승패를 고정하지 않는다.
6. 이어하기: 진행 중 운송·호위·암투·부상 상태를 저장·복원해 물자·대금·임무를 중복 처리하지 않는다.

위 항목은 사용자가 후속 구현을 직접 확인할 관찰 기준이다. 자동 빌드·실행·테스트 허가가 아니다.

# 실제 3D 쿼터뷰와 주민 생활 구현

2026-10-07. 사용자의 실제 3D 전환 및 살아 있는 NPC 구현 요청을 반영한 소스·데이터 현황이다. 빌드·실행·테스트·화면/성능 측정은 수행하지 않았다. 이전 2D 표현 및 지정 인물의 고정 사건 행동 설명보다 이 문서의 현재 범위를 우선한다.

## 1. 화면과 렌더링

- OpenGL 3.3·GLEW·freeglut을 유지한다. 카메라는 입체 월드를 바라보는 고정 직교 쿼터뷰다. HUD·대화·미니맵은 화면 좌표의 2D UI다.
- 지형, 플레이어, 주민, 몬스터, 소품, 세력 건물은 XYZ 정점과 법선이 있는 실제 입체 메시로 제출한다. 캐릭터는 후드·의복·갑옷·장비 등 부품과 관절로 구성한다.
- 기존 Actor의 x/y는 지면 X/Z에 대응한다. Terrain3D::Height는 완만한 지면 높이를 제공한다. 높이 차이에 따른 다층 길찾기·점프·낙하·실내 층별 이동·정밀 메시 충돌은 구현하지 않았다.
- MSAA 장면 FBO에 깊이 버퍼를 추가했다. 실제 깊이 검사로 앞뒤 가림을 처리하고 3D World 패스의 2D 깊이 정렬을 생략한다. 기존 후처리의 MSAA resolve·FXAA·블룸을 유지한다.
- 방향광, 카메라에 가까운 점광원 최대 12개, 2048² 그림자 맵과 3×3 PCF를 사용한다. 한 장의 그림자 맵이며 계단식 그림자·전역 조명·PBR 구현이 아니다. 물결·불꽃·유기물 맥동·거리 안개는 셰이더로 처리한다.
- 물체 표면은 월드 좌표 기반 색·거칠기 무늬와 석재 줄눈을 사용한다. UV 이미지 텍스처·외부 모델 임포터·스키닝 에셋을 추가한 것은 아니다.
- 플레이어를 가리는 큰 소품은 깊이 기록을 유지하는 디더링으로 가시성을 보완한다. 일반 반투명 메시 정렬은 현재 범위 밖이다.
- Scene은 노드의 부모·자식 3D 행렬을 합성하고, Actor 경계의 투영과 그룹 컬링을 수행한다. 클립은 3D 인스턴스에 저장해 픽셀에서 적용하며 UI scissor도 유지한다. 노드 변환은 렌더 변환이며 물리/사회 시뮬레이션의 지면 좌표를 함께 이동시키지 않는다.
- 튜토리얼도 기존 두 생존자·퀘스트 조건을 유지하면서 입체 지형/인물/소품 경로로 연결했다. VillageArt의 옛 2D 보조 함수 일부는 남지만 새 Actor 렌더 진입점에서 사용하지 않는다.

## 2. 3D 콘텐츠와 캐시

| 파일 | 역할 |
| --- | --- |
| SimpleGame/Data/models3d.catalog | 기존 31개 모델 ID 순서를 유지하고 생활 소품 5종을 더한 36개 모델 목록 |
| SimpleGame/Data/Models3D/*.mesh | 부품·관절·재질·위치·크기·회전·색 정의 |
| SimpleGame/MeshCache3D.cpp | 파일 유효성 검사, 부품 행렬 캐시, 관절 포즈와 인스턴스 제출 |
| SimpleGame/WorldRenderer3D.cpp | 단위 메시 GPU 보관, 인스턴스 배치, 그림자/조명 렌더링 |
| SimpleGame/Terrain3D.cpp | 기존 맵 정의에서 16×16 지형 청크 메시 구성 |

모두 기존 ContentData의 UTF-8 `version 1` 줄 형식을 사용한다. JSON이나 glTF가 아니다.

```
# models3d.catalog
version 1
model Pilgrim Models3D/Pilgrim.mesh

# .mesh: joint parent pivotX pivotY pivotZ
# part primitive joint material x y z sizeX sizeY sizeZ rotX rotY rotZ r g b
version 1
joint -1 0 0 0
part 0 0 1 0 0.5 0 1 1 1 0 0 0 0.3 0.3 0.28
```

primitive: 0 상자, 1 구, 2 원기둥, 3 원뿔. 크기는 단위 도형 전체 크기에 곱한다. 회전은 도 단위이며 -180~180 범위다. 관절 부모는 앞에 정의한 관절 인덱스, 루트는 -1이다. 부품 좌표와 피벗은 모델 좌표다. 재질 번호는 Renderer::Material을 따른다.

`Data/Cache/world_models3d.bin`은 별도 캐시 형식 2다. 카탈로그·메시 원문 해시가 같으면 관절/부품과 미리 계산한 로컬 행렬을 읽는다. 원문은 해시 계산을 위해 읽으며, 단위 도형 4종의 기본 정점과 GPU 자원은 실행마다 한 번 구성한다. 모든 GPU 메시가 디스크에서 바로 복원되는 캐시는 아니다. 지형은 맵 생성/복원 시 한 번 구성해 실행 중 GPU에 보관한다.

기존 2D ModelCache 형식 4와 `level1_models.bin`은 ID·콘텐츠 로더 호환을 위해 남는다. 두 캐시를 혼동하지 않는다. `.mesh` 내용만 바꿀 때 캐시 버전을 올리지 않는다. 캐시 구조나 해석 방식이 바뀔 때만 버전을 변경한다. 모델 변경은 프로그램 재시작이 필요하다. CopyGameContent가 새 원본도 배포하고 Cache는 제외한다.

## 3. 생활 계획과 실제 상호작용

첫 맵 256×200, 초기 주민 40명, 5개 세력은 유지한다. 9개 지역에 숙소·창고·진료소·재배장·시장·경계 초소·기록 작업대를 두어 총 63개 생활 장소를 정의했다. 장소는 ActivityPlace Actor로 Scene에 등록한다. 외부 파일의 장소 정원에 따라 작업 위치를 예약한다. 큰 세력 건물과는 별도의 생활 소품이다.

각 주민은 거처·작업장, 포만감, 식량 소지량, 피로, 교류 욕구, 약품, 현재 계획과 기한, 운송 물자, 상대방, 최근 약속 기억을 가진다. 우선순위와 성향·관계·위협·알고 있는 지역 정보로 계획을 선택하고 완료/취소까지 유지한다. 범용 GOAP 탐색기나 자유 의식 모델은 아니다.

- 식사: 가진 식량 1을 실제 소비하고 포만감을 회복한다. 부족하면 상대에게 지원을 요청하거나 창고에서 수령해 거처로 옮기고, 비축이 없으면 재배장 작업을 선택한다.
- 휴식: 숙소 예약 자리까지 이동해 누워 쉬며 피로를 낮춘다. 지속된 굶주림은 세계 시간의 시간 단위로 피해를 주며 무력 충돌의 피격 효과와 구분한다.
- 생산/진료: 일정 현장 작업 시간과 피로로 지역 식량을 생산한다. 진료소 약품은 유한하며 개인 수령 또는 식량을 소모하는 간략 조제 작업으로 관리한다.
- 교역: 13개 정의 경로에서 상인이 알고 있는 수요/위험과 성향을 평가하고 창고 물자를 예약해 다른 시장으로 운반한다. 배달한 식량은 개인 소지품이 된 후 실제 상대와 거래/지원한다. 지역 전체의 물가·수요곡선·소유권 경제는 아니다.
- 조사/경계: 학자는 실제 기록 장소에서 관찰 정보를 대조한다. 경비는 시장/초소를 오가며 안전 지표에 기여한다. 전쟁·위협·전투·플레이어 동행은 생활보다 우선한다.
- 소통: 요청 → 수신자 수락/거절 또는 가격 제안 → 양측 자원 예약 → 대면 전달 → 관계/기억 갱신의 상태를 저장한다. 당사자 사망·위협·기한 경과는 약속을 취소하며 미지급 대금과 생존 공급자의 물자를 반환한다. 죽은 운송자의 화물 손실은 기록한다.
- 소식은 당사자가 실제로 알고 있는 지역 관찰과 서사 증거만 전달한다. 기존 신뢰 판정·지연 메시지를 재사용하며 모든 NPC에게 세계 상태를 즉시 공개하지 않는다.

대사는 외부 문장 템플릿의 `{self}`, `{other}`, `{place}`, `{detail}`을 실제 인물·장소·자원·정보로 채운다. 발화는 요청·협의·완료·작업 상태에 연결된다. 문장을 매번 자유 생성하는 LLM, 자연어 입력 대화, 무한한 문장 다양성을 구현한 것은 아니다. 문장 다양성은 `.life`의 같은 line 키에 변형을 추가해 확장한다.

세계 갱신과 Actor 이동을 분리하며 화면 밖 주민도 기존 저빈도 갱신을 유지한다. 대화·퀘스트 수락이 활동 시작 조건이 아니다. 명시적 일시정지·능력치 창·플레이어 사망 중 세계 정지는 기존 정책대로다. 프로그램 종료 중 오프라인 진행은 없다.

## 4. 생활 데이터와 서사 연결

`Simulation/level1.society`가 `life Simulation/level1.life`를 참조한다.

```
version 1
# 작업 실시간 초, 휴식 실시간 초, 하루 식량 필요량, 교류 재시도 세계 분
rules 12 18 9 90
# ID 이름 종류 모델 지역 X Z 정원 초기약품
place refuge_rest "북부 피난지 공동 숙소" rest Bedroll refuge 33.5 45.5 5 0
# NPC_ID 숙소ID 작업장ID 초기피로 초기소지식량 초기교류욕구
resident union_0 refuge_rest refuge_market 20 4 50
# 출발 창고ID 도착 시장ID
route refuge_warehouse pilgrimage_market
line request_food "{other}, 나눌 식량이 있습니까?"
```

위는 레코드 설명용 발췌다. 실제 파일에는 모든 주민/장소 참조와 필수 대사 키를 정의해야 한다. 중복·범위·참조·모델 누락은 오류다. 작업 장소가 막힌 타일이면 가까운 접근 가능 지점으로 보정하며 10타일 이내에 없으면 로딩을 거부한다. 장소 소품 자체는 길을 막는 충돌체가 아니다.

NpcLifeData는 로딩/발화/생활 UI, NpcLife는 계획·약속·현장 작업·서사 결과, NpcLifeSave는 체크포인트를 담당한다. WorldSociety는 시간/공유 상태를 연결하고 Citizen Actor가 Scene을 통해 이동/현장 행동을 한 번 갱신한다.

생활 시스템을 켠 월드에서는 기존 StoryOrder/AdvanceStory가 지정 인물에게 정해진 사건 행동을 강제하지 않는다. LifeEvent가 실제 지원·진료·조사 결과와 해당 행위자의 지식 조건을 확인해 세 사건의 진행 상태에 반영한다. 사건 후보/증거/인물 배경은 여전히 외부 .story에 정의된다. 세 후보가 무한히 새 줄거리를 만드는 일반 서사 엔진이라는 뜻은 아니다.

## 5. 저장과 조작

- WASD 이동과 기존 전투·획득 조작을 유지한다. 기본 실행은 첫 레벨이다.
- F 대화창에 실제 발화/현재 계획을 표시한다. J → 7은 주민별 현재 계획·포만감·피로·약품·최근 약속 기억을 보여 준다. J의 기록은 개발 관찰용이며 플레이어가 모두 알고 있다는 뜻은 아니다. `[` / `]`로 페이지를 넘긴다.
- K 저장, L 불러오기, 기존 약 60초 자동 저장을 유지한다. 저장 `save_schema 4`에는 생활 계획·현장 진행량·예약 자리·운송 화물·약품·거래 예약 자원·약속 단계·인물과 몬스터 방향·실제 사건 참여자를 포함한다.
- schema 3 이하 저장은 자동 변환하지 않는다. 복원 실패 시 기존 파일을 유지하고 자동 저장을 중지한다. K는 현재 새 세계를 저장하므로 옛 진행을 보관하려면 먼저 `Saves/world.save`와 `.bak`을 별도 보관한다. 이번 작업에서 사용자 저장을 삭제/이동하지 않았다.
- 정의 해시와 예약 참조/중복 자리/약속 양측 검사를 유지한다. 내용이 바뀐 `.life`도 저장 호환성에 영향을 준다. GPU 캐시/생활 원본/플레이 저장은 서로 다르다.

## 6. 성능과 다음 확인

기본 도형 4종별 인스턴싱을 그림자/본 렌더에 재사용하며 지형 정점은 청크별 GPU에 보관한다. 한 프레임마다 맵 전체의 정점을 다시 포장하지 않는다. 그림자 패스와 지형 청크로 실제 draw call은 이전 2D 배치의 19회와 달라질 수 있다. draw call 숫자만으로 성능을 단정하지 않는다.

기존 JSONL에 `cpu_world_3d_ms`, `cpu_shadow_3d_submit_ms`, `world_3d_instance_count`, `world_3d_submitted_triangle_count`, `cpu_npc_life_ms`, `npc_active_plan_count`, `npc_active_agreement_count`를 추가했다. 자세한 포함 관계는 PERFORMANCE_PROFILING.md를 따른다. 60 FPS 달성이나 그림자/화면 품질은 아직 확인하지 않았다.

사용자가 확인할 순서:
1. 첫 실행 콘텐츠 로딩과 실제 입체 캐릭터/건물/지형의 깊이 가림, 그림자, 물결·불꽃, 한국어 UI.
2. 플레이어가 대화하지 않아도 주민이 일터/시장/숙소로 이동하는지와 운반·작업·대화·휴식 포즈.
3. J 7과 실제 행동이 맞는지, 요청 후 상대 수락/거절과 식량·약품·관계 변화가 일치하는지.
4. 화면 밖으로 떠났다가 돌아왔을 때 진행이 유지되는지, 전투/사망이 약속을 중단시키는지.
5. 물자를 든 상태와 거래 수락 중 K/L 후 물자 중복 없이 이어지는지.
6. 같은 시드·해상도·구성에서 JSONL의 프레임 p95, 3D 제출 CPU, GPU geometry, NPC 경로/생활 시간을 비교.

다음 조정은 실제 화면과 로그를 받은 뒤 가독성·동작 속도·그림자 해상도·NPC 작업 빈도 순으로 진행한다. 빌드/테스트를 자동 수행한다는 뜻은 아니다.

## 7. 2026-10-08 후속 구현

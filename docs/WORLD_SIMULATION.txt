# 월드 시뮬레이션 1차 구현 — 2026-09-28

## 범위

OpenGL 3.3·freeglut, 기존 Actor·Scene Graph·전투·외부 콘텐츠 구조를 유지한다.
전체 오픈 월드 스토리 사양 중 15분 작업 범위의 기반만 구현했다.
월드 시간 → 지역 식량/감염 지표 → 조건부 사건 1종 → 한국어 HUD와 로그가 연결된다.
세력, 자율 NPC, 관계망, 동적 퀘스트, 사건 선택지, 재실행 간 저장은 미구현이다.
새 NPC·건물·식량 아이템·시각 효과를 배치한 구현이 아니다.

## 코드와 데이터

- WorldSimulation.h/.cpp: 독립적인 시간 누적, 지역 상태, 사건 조건/효과/재발 대기.
- LevelData::Load: .world의 선택적 simulation 경로를 읽는다. 경로가 없으면 시뮬레이션을 사용하지 않는다.
- LevelOne::Generate: 후보 데이터와 시뮬레이션을 로딩한 후 맵 생성까지 성공하면 교체한다. 실패하면 기존 월드와 상태를 유지한다.
- LevelOne::Update: 기존 일시정지 검사 뒤 시뮬레이션을 진행한다. 배치 Actor 업데이트는 계속 Scene을 사용한다.
- LevelOne::DrawUI: 기존 HUD Actor에서 세계 시각, 현재 구역의 식량/감염 백분율, 최근 사건을 한국어로 표시한다. 시각/식량/감염 라벨을 나눠 기존 텍스트 캐시를 재사용한다.
- SimpleGame/Data/Levels/level1.world → simulation Simulation/level1.sim.
- SimpleGame/Data/Simulation/level1.sim: 기존 ContentData의 version 1 UTF-8 줄 단위 형식. JSON이 아니다.

## 파일 형식

첫 유효 줄은 `version 1`이다. # 주석과 따옴표 문자열을 지원한다.

```
clock 360 2
region refuge .65 .22 -.08 .04
event fungal_provisions .35 .40 180 .18 .06 "균사 식량 출현 · 굶주림 완화, 감염 증가"
```

- clock: 시작일 내 분(0~1439), 실제 플레이 진행 1초당 월드 분(.01~60). 한 번만 정의한다.
- region: .world 지역 ID, 초기 식량(0~1), 초기 감염(0~1), 월드 1시간당 식량 변화(-1~1), 감염 변화(-1~1).
- 모든 .world 지역에 region 레코드가 하나씩 필요하다. 미등록 ID·중복·잘못된 범위는 오류다.
- event: ID, 식량 이하 임계값, 감염 이상 임계값, 지역별 재발 대기(월드 분, 1~10080), 식량 변화, 감염 변화, 한국어 알림.
- 이번 단계는 event 하나만 지원한다. 알림은 UTF-8 180바이트 이하이며 현재 HUD용으로 짧게 작성한다.
- 식량·감염 수치는 플레이어 소지품/개인 감염이 아닌 지역의 추상적인 상태 지표다. 전투 수치에 영향을 주지 않는다.

## 진행 규칙

처음 실행하면 1일 06:00, 실제 플레이 진행 1초 = 월드 2분이다.
소수점 누적분을 보존하고 월드 1분마다 모든 지역을 갱신한다. 프레임마다 시간을 정수로 버리지 않는다.
시간 변화량은 시간당 수치 / 60으로 적용하고 0~1 범위로 제한한다.
최대 120분을 한 Update에서 처리하며 초과 누적분은 다음 Update로 남긴다. 현재 게임의 제한된 dt에서는 통상 0~3분 처리다.
일시정지·능력치 창·사망 중에는 세계와 알림 시간이 멈춘다. 실제 벽시계·백그라운드 경과 시간을 따라잡는 기능은 없다.

사건은 식량 <= 35%, 감염 >= 40%일 때 해당 지역에서 발생한다.
균사 식량 출현으로 식량 +18%p, 감염 +6%p를 적용하고 그 지역은 월드 180분 동안 재발하지 않는다.
기본 설정의 첫 사건은 성혈의 습지에서 플레이 진행 약 21~22초 후 예상된다. 이는 데이터 계산이며 실측 결과가 아니다.
생존을 돕는 균사와 감염 의존이라는 양면성을 표현하며, 감염 제거를 일방적인 정답으로 삼지 않는다.
여러 지역 사건이 연달아 발생하면 HUD에는 가장 최근 소식만 18초 동안 표시한다. 전체 사건은 JSONL에 기록한다.

## 재생성과 데이터 오류

같은 월드/시뮬레이션 파일을 R로 다시 로딩할 때 시간·소수점 누적·기존 지역 식량/감염을 ID로 유지한다.
사건 ID도 같으면 지역별 재발 예정 시각을 유지한다. 새 지역은 파일 초기값으로 시작한다.
변화율·조건·효과는 성공적으로 로딩한 새 정의를 사용한다. 이미 예약된 재발 시각은 바꾸지 않는다.
초기 식량/감염과 시작 시각 변경은 프로그램 재시작으로 확인한다. 재실행 저장은 없다.
파일이 누락되거나 잘못되면 초기 진입을 중단하거나 기존 맵을 유지하고 콘솔/프로파일에 오류를 남긴다.
원본 Data는 사용자 빌드의 기존 CopyGameContent에서 배포 Data로 복사된다. 실행 중 R은 배포 Data를 읽는다.

## 프로파일링

- cpu_world_simulation_ms: Update의 CPU 경과 시간. 상위 cpu_update_ms와 합산하지 않는다.
- world_minute_tick_count: 프레임 내 처리한 월드 분 수.
- world_event_count: 프레임 내 발생한 사건 수.
- world_absolute_minute: 시작일 00:00 기준 현재 분 게이지.
- world_simulated_region_count: 시뮬레이션 대상 지역 수 게이지.
- player_region_food_ratio / player_region_infection_ratio: 현재 플레이어 지역 상태, 0~1 게이지.
- world_player_region 이벤트: 현재 지역 ID와 시간 배율. 지역 변경/재로딩 후 기록한다.
- world_region_state 이벤트: 월드 정시에 모든 지역 상태를 기록한다. 해당 분의 사건 효과 적용 직전 상태다.
- world_event 이벤트: 사건 ID, 지역 ID, 월드 분, 식량·감염 적용 전후 값.
- 이벤트 detail은 기존 JSONL 규약의 문자열이며 key=value 쌍을 포함한다. 새 중첩 JSON 스키마라고 해석하지 않는다.
- 게이지의 sum은 누적 자원량이 아니다. 프레임 통계의 mean/p95/max와 사건별 지역 ID를 함께 본다.

## 사용자가 확인할 항목

빌드·실행·테스트·화면 확인은 수행하지 않았다.
1. 첫 레벨 하단 시각과 현재 구역 수치가 표시되는지 확인한다.
2. 약 22초 이상 플레이하여 성혈의 습지 사건 알림과 world_event 로그를 확인한다.
3. Tab/ESC/사망 시 시각이 멈추고 정상 플레이로 복귀할 때 이어지는지 확인한다.
4. 시작 제단의 R 재생성 후 시간/지역 수치가 유지되는지 확인한다.
5. 작은 창에서도 하단 안내·알림이 겹치지 않는지 확인한다.
6. 이전과 동일한 실행 조건에서 cpu_world_simulation_ms와 프레임 p95를 비교한다.

다음 단계는 실행 로그와 진행 속도를 확인한 뒤 사건에 플레이어 선택 또는 퀘스트 하나를 연결하는 것이다.

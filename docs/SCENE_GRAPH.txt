# Scene Graph 기반 제어

기준일: 2026-09-22. 코드에 반영한 구조를 설명한다. 사용자 지침에 따라 빌드·실행·테스트·화면 확인과 성능 측정은 수행하지 않았다.

## 이번 변경

기존 Scene은 프레임마다 Actor 포인터를 모으는 평면 렌더 목록이었다. 이제 Game과 LevelOne 각각이 Scene을 멤버로 유지하고, 레벨 구성 시 부모·자식 노드와 Actor를 등록한다. 업데이트와 렌더링 모두 Scene이 순회한다.

Actor의 메모리 소유는 레벨에 유지하고 Scene은 노드 트리를 소유한다. 렌더링 자원은 Renderer와 ModelCache가 계속 담당한다.

## 현재 계층

```text
Root
├─ World
│  ├─ Terrain → 지형 Actor
│  ├─ Static sectors → 8×8 배치 구역 → 건물·장식 Actor
│  ├─ Characters → 플레이어 → 경로 계산 → 적 Actor들
│  ├─ Loot → 아이템 Actor들
│  └─ Floating text → 피해·경험치 Actor들
└─ UI
   ├─ HUD → 체력·경험치·안내
   ├─ Minimap clip → 미니맵
   └─ Menus → 능력치·일시정지·사망 화면
```

위 구조는 첫 전투 레벨이다. 튜토리얼은 Footprints, Village sectors, Characters, Atmosphere, UI 그룹으로 구성한다. 정적 구역은 초기 배치 좌표로 나누고 경계는 실제 현재 Actor 위치에서 다시 계산한다. 개별 Actor를 이동해도 예전 구역 경계 때문에 사라지지 않는다. 이동한 객체를 다른 구역에 자동 재배치하는 공간 재분할은 현재 하지 않는다.

## 업데이트

- 레벨은 시간·카메라·퀘스트를 관리하고 Actor 업데이트는 Scene::Update에 맡긴다. Actor별 Update를 레벨에서 중복 호출하지 않는다.
- 부모에서 자식으로 활성화와 표시 상태를 전파한다. 그룹 비활성화는 자식 업데이트·렌더링을 중단하고, 그룹 숨김은 렌더링만 중단한다. 상태 전파는 다음 Update 또는 Render 순회 시작에 반영한다.
- 첫 레벨은 플레이어 이동/공격 → 경로 계산용 Actor → 적 AI 순서를 유지한다.
- 정적 배치·지형·HUD 등 개별 OnUpdate 처리가 없는 Actor는 SetTickEnabled(false)로 불필요한 호출을 생략한다. 이 상태는 표시·충돌·상호작용을 끄지 않는다. 새 로직을 추가하면 Tick을 다시 켠다.
- 카메라 밖이라는 이유로 적 AI·피해 숫자·발자국 수명 처리를 멈추지 않는다. 렌더링 컬링과 게임 업데이트 정책을 구분한다.
- 공격 중 생성한 전리품·피해 숫자는 등록 대기열에 넣고 순회 종료 후 그래프에 연결한다. 같은 프레임에 그릴 수 있으며 업데이트는 다음 틱부터 시작한다.

## 화면 밖 제외와 정렬

Actor::SetRenderBounds는 월드 객체 발밑의 쿼터뷰 투영 지점에 대한 픽셀 단위 경계를 지정한다. 화면 좌표 그룹에서는 Actor x/y에 대한 경계다. 그림자·불꽃·공격 범위·체력 막대까지 포함하도록 여유를 둔다. 실제 캐릭터 충돌 범위와는 다르다.

Scene은 매 Render에서 자식 경계를 합쳐 부모의 경계를 계산한다. 화면 또는 상속한 클립 영역과 그룹 전체가 겹치지 않으면 해당 하위 트리의 렌더 후보 수집을 생략한다. 그룹이 걸쳐 있으면 개별 Actor까지 검사한다. 보이는 월드 Actor만 Depth 순으로 안정 정렬한다.

경계가 없는 지형·분위기·HUD는 보수적으로 렌더 후보에 남긴다. 지형 내부의 기존 타일별 화면 밖 제외도 유지한다. 경계 계산은 노드 수에 비례하는 작업이며, 트리 순회 비용까지 사라지는 것은 아니다. 이번 최적화의 중심은 비싼 도형 조립·제출과 불필요한 정렬·렌더 콜백을 줄이는 것이다.

Actor::SetRenderPasses로 필요한 패스를 명시한다. 바닥·그림자·월드·효과·오버레이·UI 중 사용하지 않는 단계에는 콜백을 호출하지 않는다. 예를 들어 전리품은 World, 떠오르는 숫자는 Overlay, 미니맵은 UI에만 참여한다. 화면에 직접 그리지 않는 도로 메타데이터와 경로 계산용 Actor는 렌더 마스크가 0이다.

## 클리핑

Scene::Node::SetClipRect는 화면 왼쪽 위 기준 픽셀 좌표의 left/top/right/bottom 사각형이다. 자식의 클립은 부모 클립·자신의 클립·현재 화면의 교집합으로 제한한다. 빈 영역이면 하위 트리를 그리지 않는다. ClearClipRect는 자신의 제한을 해제하지만 부모 제한은 유지한다.

첫 레벨 미니맵을 별도 Actor와 클립 그룹으로 분리해 실제 적용했다. 창 크기에 따라 영역을 갱신한다. 능력치·일시정지 화면은 형제 그룹이므로 미니맵 영역으로 잘리지 않는다.

부분적으로 걸친 도형은 Renderer::SetClipRect의 GL_SCISSOR_TEST로 자른다. 클립이 달라질 때만 이전 배치를 Flush하고 상태를 바꾼다. 동일한 클립의 연속 Actor는 배치를 유지한다. 장면 후처리 전에 클립을 해제해 MSAA 리졸브·블룸·최종 합성이 미니맵 같은 좁은 영역에 갇히지 않게 한다.

## 수명과 등록 규칙

1. CreateGroup으로 해당 Scene의 부모 아래 새 노드를 만든다. 새 노드만 연결하므로 순환 구조를 만들지 않는다. 그룹 생성·Clear는 순회 밖에서 수행한다.
2. 주소가 유지되는 Actor를 Attach로 등록한다. 같은 Scene에 같은 Actor를 중복 등록해도 노드를 추가하지 않는다.
3. 업데이트 중 Attach는 대기열로 처리한다. Actor 자체는 레벨이 보관하며 등록 전후 모두 살아 있어야 한다.
4. Destroy된 Actor는 Scene::Update 마지막에 노드부터 제거한다. 레벨은 그 뒤 실제 객체를 컨테이너에서 제거한다. 업데이트 없이 수동 정리한다면 먼저 Scene::RemoveDestroyed를 호출한다.
5. 레벨 재생성·재시작 시 Scene::Clear를 먼저 호출하고 Actor 컨테이너를 정리한 뒤 트리를 다시 구성한다. Clear 이후 기존 Node 참조를 사용하지 않는다.

자주 추가·제거하는 전리품·피해 숫자·발자국은 std::list에 보관해 다른 객체의 주소를 유지한다. 정적 Object·Prop과 생성 후 원소를 추가하지 않는 Enemy는 기존 vector를 유지한다. 이 vector를 재할당하거나 중간 원소를 이동시키기 전에는 반드시 그래프에서 분리해야 한다.

Graph는 Actor를 delete하지 않는다. Destroy와 적의 사망도 구분한다. 사망한 적의 Actor는 시체 표현을 위해 남긴다.

## 측정과 범위

Scene::GetStatistics에서 이번 업데이트의 updatedActors와 마지막 렌더링의 visibleActors·culledActors·culledGroups를 읽을 수 있다. culled 수는 화면/클립 검사로 제외된 수이며, 비활성·숨김·렌더 마스크 0인 객체는 포함하지 않는다. visibleActors는 렌더 후보 수로, 실제 픽셀 가시성이나 draw call 수와 동일하지 않다.

기존 프레임별 OpenGL draw call 콘솔 출력은 유지했다. 원래도 여러 도형을 한 번에 제출하므로 컬링 후 정점 수가 줄어도 draw call 수가 같을 수 있다. 서로 다른 클립은 배치를 나누므로 draw call 수만으로 최적화 효과를 단정하지 않는다. 성능 향상 수치는 아직 측정하지 않았다.

이번 그래프는 현재 2.5D 화면에 맞춘 계층 순회·상태 상속·사각 경계 컬링·클리핑·패스 선택을 담당한다. Actor 위치는 기존 월드 좌표다. 부모의 이동·회전·스케일을 자식 좌표에 곱하는 변환 계층, 3D 절두체/오클루전 컬링, 자동 LOD·인스턴싱은 추가하지 않았다.

## 사용자 확인 순서

1. 직접 빌드 후 튜토리얼 이동·발자국·NPC·건물 가림과 첫 레벨 입장을 확인한다.
2. 첫 레벨에서 적 처치·아이템 획득·피해 숫자 생성/소멸이 반복되는지 확인한다.
3. 화면 가장자리에 걸친 캐릭터·큰 건물·화로·그림자가 너무 일찍 사라지지 않는지 확인한다.
4. 창 크기를 바꾸어 미니맵 클리핑과 Tab/Esc 화면이 서로 영향을 주지 않는지 확인한다.
5. 사망 재도전·R 맵 재생성을 반복해 이전 노드가 남거나 참조 오류가 생기지 않는지 확인한다.
6. 필요하면 디버거에서 Scene 통계와 기존 draw call 로그를 함께 비교한다. CPU/GPU 시간·정점 수 측정은 별도 후속 작업이다.

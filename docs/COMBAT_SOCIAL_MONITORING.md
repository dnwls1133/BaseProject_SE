# 공격·생활 판단·로컬 월드 모니터 — 2026-10-12

소스 구현 상태다. 빌드·실행·테스트·화면 품질·성능 확인은 수행하지 않았으며 사용자가 담당한다.

## 공격 판정과 표현

- 기존 NPC→몬스터 피해는 `max(1, NPC 공격력 - 몬스터 방어력)`이었다. 피해를 막는 의도는 아니다. 용기 0.5 미만 또는 체력 30 미만 NPC는 도주하고, 세력별 ecology 친화도가 0 이상인 종은 공격하지 않는다.
- 이전에는 공격 준비 중 사거리/시야 조건이 깨지면 즉시 준비 시간을 초기화했다. 변경 후에는 시작한 준비를 완료하고 타격 순간 사거리+0.35 타일과 시야로 명중/빗나감을 판정한다. 멀리 달아나거나 벽 뒤로 간 대상에게 자동 명중시키지 않는다. 대상 사망, 위협 해제, 도주 등의 취소 조건은 유지한다.
- NPC 대 NPC, NPC 대 몬스터, NPC 대 플레이어에 동일한 준비/타격 원칙을 적용했다. 타격 후 0.3초 표현 시간과 대상 방향을 연결했다. 실제 전투 수치나 방어력은 변경하지 않았다.
- MeshCache3D의 기존 관절에 준비 자세, 몸통 회전, 양팔/다리 자세, 휘두르기와 회복을 연결했다. 플레이어 표현의 준비 구간은 외부 rpg.rules의 attackHitTime에 맞춘다. 검격 궤적은 기존 3D 인스턴스 배치를 사용한다. 몬스터 피격 파편과 NPC가 준 피해 숫자도 표시한다. 외부 스키닝/모션 캡처 애니메이션을 추가한 것은 아니다.
- NPC의 attack_attempts는 완료한 타격 시도이며 준비 취소는 포함하지 않는다. attack_hits/misses와 last_attack으로 완료 판정을 구분한다. damage_dealt는 NPC/몬스터 체력의 실제 감소량이다. 플레이어 대상 피해는 방어력/무적/복수 공격 합산을 별도 처리하므로 이 누적량에서 제외한다. 이 진단과 strikeTime은 세이브 대상이 아니며 새 실행/초기화 시 초기값이다.

## 생활과 교역의 변경 범위

`NpcLife::ChooseLife`는 생존/심한 피로/기존 약속을 우선한다. 일반 생활 선택은 휴식, 식사, 배급 수령, 농장, 진료소, 경비, 기록 조사, 시장, 교역로를 함께 비교한다. 정보/서사 가중치, 직책과 성향, 지역 수요, 관찰한 부상자, 피로, 여행 시간, 알고 있는 감염 위험이 점수에 영향을 준다. 원거리 수요는 받은 보고의 신뢰도/유효기간으로 판단한다. 정보 요청은 새로운 지역 보고 또는 아직 모르는 증거가 있는 상대를 우선한다.

교역 후보도 일반 작업과 경쟁한다. 교역에 실패한 약속의 기억과 피로는 먼 여행의 비용을 높인다. 수신자의 식량 부족분만 거래하고 남은 화물은 실제 목적지 창고에 넣는다. 판매자 탐욕/연민, 수신자 부족분, 개인 관계가 가격에 영향을 주며 지급 불가능한 상대는 후보에서 제외한다.

실행 단계는 여전히 유한한 작업 상태와 약속 단계다. 상태 머신 자체를 없앤 것이 아니라, 실행할 목표를 비교하는 판단을 보강했다. 양측 가격 재협상, 부채/배급권, 장기 이주, 호위 계약과 정치적 거래, 범용 GOAP는 아직 구현하지 않았다. 단순 점수 보강으로 컨셉 전체를 완성했다고 해석하지 않는다. candidate_scores/choices는 마지막 일반 판단의 기록이며 실시간 전투/긴급 조건의 후보 점수는 아니다.

## 로컬 HTML 사용

가장 간단한 시작 방법은 파일 탐색기에서 `tools/world_monitor/start.cmd`를 더블클릭하는 것이다. 서버가 포트를 연 뒤 기본 브라우저를 연다. 서버 터미널 창은 열어 둔다. 게임을 켜는 것만으로 웹 서버가 실행되지는 않는다.

게임은 실행 파일 옆 `Logs/WorldMonitor/snapshot.json`을 약 1초마다 갱신한다. 게임 스레드에서 완결된 JSON을 복사하고 작업 스레드에서 임시 파일→교체로 저장한다. 작업 스레드는 월드 객체를 읽지 않는다. 미처 저장하지 못한 중간 샘플은 최신 샘플로 교체하며 무한 대기열을 만들지 않는다. 일시정지/능력치 창/사망 상태도 첫 레벨 Update 호출이 유지되면 갱신한다. 게임 종료 또는 다른 레벨 전환 후에는 마지막 상태만 남고 HTML에 갱신 중단이 표시된다.

프로젝트 루트에서 다음 PowerShell 스크립트를 실행한다. 설치된 py, Codex 번들 Python, 일반 python 순으로 찾으며 Python 표준 라이브러리만 사용한다.

```powershell
.\tools\world_monitor\start.ps1
```

Python 3 실행기가 있는 환경에서는 `py -3 tools/world_monitor/serve.py`를 직접 사용해도 된다.

브라우저에서 `http://127.0.0.1:8765`를 연다. 서버 종료는 Ctrl+C다. 게임과 서버는 사용자가 직접 실행한다. 서버는 로컬 주소에만 바인딩하고 읽기만 제공한다. 원격 접근이나 게임 명령 수신 기능은 없다. 기본은 x64/Debug 또는 Release의 기존 스냅샷 중 가장 최근 파일이 있는 폴더를 시작 시 선택하며, 이후 자동으로 실행 구성 간 전환하지 않는다.

다른 실행 구성/경로 또는 포트는 다음처럼 지정한다.

```powershell
py -3 tools/world_monitor/serve.py --port 8766 --snapshot-dir "C:\게임실행폴더\Logs\WorldMonitor"
```

HTML 파일을 파일 탐색기에서 직접 열지 않고 위 HTTP 주소로 접속한다. `/api/state`에서 JSON을 약 1초 간격 HTTP polling으로 수신한다. WebSocket/SSE 방식은 아니며 외부 패키지나 런타임 LLM은 필요 없다.

## 표시 항목과 JSON

- 모든 NPC: 안정적인 NPC ID, 세력/직책/목표, 생존/HP/식량/감염, 위치/지역, 행동/대상, 허기/피로/사회 욕구, 화물/약품/약속, 진행/정체 시간, 선택 이유, 정렬한 후보 점수, 최근 관계 기억, 공격 시도/명중/빗나감/피해.
- 마을별 상태: 현행 맵의 9개 지역을 관리 단위로 표시한다. 소유 세력, 생존 주민/몹, 지역 식량/감염 비율, 치안/공포/불만/성혈/군집/시설 상태. 별도 마을 경제 시뮬레이션을 새로 만든 것은 아니다.
- 개체 수: 전체/생존/사망 NPC 및 몬스터, 활성 몬스터 수. 시체가 남아 있어도 생존 수에 포함하지 않는다.
- 세력 보급/지지/구성원, 세력 간 관계 수치(JSON), 양측 약속의 종류/단계/화물/대금, 진행 중 원정, 인과관계 ID가 있는 최근 세계 사건, 지도상 위치. 검색/세력/생존 필터와 NPC 상세 조회, JSON 다운로드를 제공한다.
- JSON schema_version=1. session_id는 프로세스 ID, sequence는 세션 내 샘플 순번, sampled_at_unix_ms는 실제 수집 시각, world_minute는 세계 시각이다. 누락된 지역 측정값은 null이다. monsters의 ID는 기존 배열 인덱스 기반이라 맵 재생성 사이의 영속 ID는 아니다.
- cpu_world_monitor_snapshot_ms는 게임 스레드 JSON 구성/제출 비용이다. 별도 작업 스레드 파일 I/O 시간까지 포함하지 않는다. 쓰기 실패 시 콘솔의 world_monitor_write_error와 HTML의 오래된 수집 시각으로 확인한다. 스냅샷은 자동 제외하며 세이브 파일과 별개다.

## 직접 확인할 항목

1. 플레이어와 NPC가 준비→타격→회복 동작을 보여 주고 공격 대상을 바라보는지.
2. 적대 변이체와 교전 중인 NPC의 attack_hits/damage_dealt가 증가하고 몬스터 HP가 감소하는지. 공격 안 함, 준비 취소, 빗나감, 낮은 피해를 구분한다.
3. 식량·피로·받은 보고가 달라질 때 일반 후보 점수/계획이 달라지는지. 플레이어 대화 없이 교역과 전투가 진행되는지.
4. 실제 화물 감소, 수신자 식량 증가, 세력 보급 지급, 잔여 창고 입고가 일치하는지.
5. HTML의 수신 순번/시각이 증가하는지, 일시정지와 종료를 구분하는지, 40명 목록과 지역별 생존 수가 표시되는지.
6. cpu_world_monitor_snapshot_ms와 기존 CPU/GPU/p95 프레임 지표로 새 모니터/효과 비용을 확인한다. 성능 개선 또는 60 FPS 달성을 단정하지 않는다.

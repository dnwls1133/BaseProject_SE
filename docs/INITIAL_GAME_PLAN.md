## 2. 핵심 콘셉트와 기획 의도

인류를 구원한 성혈은 외우주에서 온 기생형 진균이었다. 감염체 없이는 살아갈 수 없게 된 주인공이 무너진 신성 제국을 탐험하며, 몸·기억·의지 중 무엇을 지켜야 인간으로 남는지 선택한다.

기획의 중심은 다음 세 가지다.

1. 구원의 역전: 치료와 생존의 수단이 변이와 자아 상실의 원인이 된다.
2. 인간성의 갈등: 인간의 외형과 인간다운 행동을 분리하고, 선택의 결과로 주제를 전달한다.
3. 이해할 수 없는 우주: 감염 현상은 조사할 수 있지만 그 너머의 존재와 목적을 모두 해명하지 않는다.

플레이어가 느낄 감정은 생존의 불안, 탐험을 통한 호기심, 타인에 대한 연민, 자신의 정체성에 대한 의심이다. 분위기가 절망적이어도 행동의 결과는 남아야 한다. 한 사람의 자아나 작은 공동체를 지키는 성취가 여정을 지속하게 한다.

## 3. 시간적 배경과 세계관

### 역사

| 시기 | 사건 |
|---|---|
| 유성 이전 | 극심한 역병과 기근으로 대륙이 멸망 직전에 놓인다. |
| 유성 낙하 | 핏빛 유성 중심부의 액체가 병을 낫게 하고 죽어가는 사람을 살린다. |
| 제국 성립 | 교단이 액체를 성혈(Holy Blood)로 명명하고 성인에게 투여한다. 기적을 기반으로 거대한 신성 제국이 세워진다. |
| 수백 년의 축적 | 성혈이 축적되며 인간의 생존과 감염이 분리될 수 없게 된다. |
| 게임의 현재 | 육체에서 외우주의 식생과 뼈가 자라고, 자아를 잃은 감염자들이 군집의 속삭임에 조종된다. 교단은 변이를 천사로의 우화라 선포한다. |

정확한 연도는 미정이다. 중세 말기~초기 근세의 건축·기술 양식은 기존 제안이며 확정 설정은 아니다.

### 성혈과 새로운 인류

성혈의 실체는 기생형 진균과 포자로 이루어진 외우주 감염체다. 기존 기준안에서는 감염체가 손상된 장기와 신경을 대체하므로, 제거하면 숙주도 죽을 수 있다. 감염자는 다음처럼 서로 다른 상태로 등장한다.

- 자아를 잃은 변이체: 군집에 조종되며 위협이 된다.
- 자아를 유지한 감염자: 기괴한 육체로 살아가지만 기억과 판단력을 유지한다.
- 연결된 공동체: 감각·기억·고통을 공유한다. 연대와 개인의 자유가 충돌한다.

외형만으로 적과 우호 대상을 판정하지 않는다. 변이 자체를 도덕적 타락으로 취급하지 않는다.

### 코스믹 호러 원칙

- 낯선 기억, 서로 다른 인물의 같은 꿈, 시간적으로 모순된 증언으로 불안을 축적한다.
- 생물학적 단서는 제시하되 외우주 존재의 의도와 전체 규모는 남겨둔다.
- 유성 중심부는 기준안에서 신호의 수신 기관이다. 그 발견이 우주의 모든 진실을 설명하지는 않는다.
- 모든 기억이 거짓이라는 반전으로 플레이어의 경험을 무효화하지 않는다.
- 교단의 교리, 관측 기록, 인물의 증언을 구분하여 어느 설명이 사실인지 신중하게 드러낸다.

## 4. 플레이어와 핵심 플레이 구조

주인공 기준안은 성혈로 연명하며 자아를 유지하는 감염자다. 초반 목표는 변이를 멈출 치료 기록을 찾는 것이고, 후반에는 자아와 생존을 함께 지킬 방법을 찾는 것으로 바뀐다. 이름·과거·직업·커스터마이징은 미정이다.

기본 플레이 순환 제안:

탐험 → 위협·인물·기록 발견 → 전투 또는 상호작용 → 자원·정보 획득 → 선택과 지역 변화 → 다음 지역 탐험

| 시스템 | 초기 설계 방향 | 결정이 필요한 부분 |
|---|---|---|
| 이동·탐험 | 쿼터뷰에서 위치와 이동 방향이 명확하고 카메라가 플레이어를 추적 | 입력 방식, 높이 이동, 이동 제한 |
| 전투 | 실시간 게임 흐름에 맞는 소규모 전투부터 설계 | 공격·회피·방어, 자원, 사망 패널티. 소울류 배경을 특정 전투 규칙으로 자동 확정하지 않음 |
| 성혈 | 생존 수단이면서 변이와 관계되는 핵심 소재 | 회복 아이템화, 변이 수치, 능력 변화 여부와 대가 |
| 성장·장비 | RPG 확장 대상으로 관리 | 레벨·능력치·스킬·장비 구조 |
| 상호작용·퀘스트 | 대화와 조사, 선택, 상태 변화로 인간성 주제를 표현 | 대화 UI와 분기 조건 |
| 저장 | 플레이어와 월드 변경 상태를 원본 콘텐츠와 분리 | 저장 시점, 슬롯, 사망 후 유지 범위 |

치유의 대가를 구현하더라도 기본 회복을 사용했다는 이유만으로 예고 없이 엔딩을 차단하지 않는다. 결과를 예상할 단서와 대응 수단을 제공하는 방향을 제안한다.

## 5. 오픈 월드와 지역 구성

서막 이후 주요 세 지역을 자유로운 순서로 탐험하는 구조를 기준으로 한다. 성도 진입에는 세 증표가 필요하다. 자유 탐험과 메인 진행 조건을 병행하며, 초기에는 작은 연결 구역으로 검증한 구조를 확장한다. 전체 맵 크기·완전 무로딩 여부·절차적 생성은 미정이다.

| 지역 | 역할 | 핵심 경험 |
|---|---|---|
| 파괴된 마을 | 서막 | 감염자 한 명의 부탁과 성혈 의존 |
| 첫 피난촌 | 초기 거점 | 치료 기록의 단서와 여정의 목적 |
| 부패한 수도원 | 육체 분기 | 변이한 성인과 피난민의 생존 |
| 침수된 서고 | 기억 분기 | 주인공의 과거와 타인의 기록 충돌 |
| 포자 숲의 정착지 | 의지 분기 | 군집의 안식과 이탈할 권리 |
| 성도·대성당 | 후반 | 교단의 치료와 우화의 실체 |
| 유성 중심부 | 종막 | 외우주 신호와 대륙의 미래 선택 |

풍경·건축·적 배치·기록으로 지역의 역사를 전달한다. 주요 길과 상호작용 대상은 배경 오염 표현 속에서도 식별되게 한다.

## 6. 메인 퀘스트 흐름

서막 ‘죽지 못한 자’ → 1막 ‘기적이 썩은 땅’ → 세 지역 자유 탐험 → 2막 ‘천사들의 성도’ → 3막 ‘하늘 아래의 수신기’ → 결말 분기.

| 단계 | 사건과 목표 |
|---|---|
| 서막 | 파괴된 마을에서 위독한 감염자에게 마지막 성혈을 가져다주고 성도로 향할 단서를 얻는다. |
| 1막 진입 | 피난촌에서 성도의 치료 기록을 알게 되고 세 성인의 증표를 찾는다. |
| 육체: 뿌리내린 수호자 | 벽에 융합된 성인의 요청에 따라 죽음을 돕거나 공생을 유지한다. 육체의 증표 획득. |
| 기억: 타인의 고향 | 자신의 기억과 오래된 기록이 일치한다. 공개하거나 봉인한다. 기억의 증표 획득. |
| 의지: 슬픔 없는 마을 | 군집에서 나가려는 주민을 돕거나 동의 아래 다른 연결 방법을 찾는다. 의지의 증표 획득. |
| 2막 | 세 증표로 성도 봉인을 연다. 교단의 치료가 자아를 지우는 의식임을 발견한다. |
| 3막 | 유성 중심부가 외우주 신호를 받는 기관임을 발견하고 우화 의식과 대륙의 연결에 개입한다. |

세 지역의 어느 선택으로도 메인 진행에 필요한 증표를 얻는다. 분기 결과는 인물·지역·대사에 남는다. 증표를 얻는 구체적 사건과 전투 여부는 후속 설계한다.

| 결말 | 선택 | 남는 대가 |
|---|---|---|
| 단절 | 외부 신호와 대륙의 감염망을 끊음 | 개인의 의지는 남지만 성혈 의존 생명과 문명이 쇠퇴 |
| 합일 | 군집 연결을 완성 | 고통과 기근이 사라지는 대신 개인의 존속은 불확실 |
| 불완전한 공존 | 지역 연결을 남기고 강제 동기화를 억제 | 자아와 생존의 가능성을 지키지만 감염과 속삭임 지속 |

공존은 공생 유지·기억의 경계·자발적 연결에 관한 지식으로 열리는 기준안이다. 정확한 조건은 미정이며 정답 엔딩으로 취급하지 않는다.

## 7. 시청각 방향

아래 세부 표현은 제작 제안이다.

- 시각: 퇴색한 석조 건축, 차가운 그림자와 회백색 균사, 핏빛 성혈을 대비한다. 밝기만 낮춰 분위기를 만들지 않는다.
- 형태: 종교적 장식과 골격·뿌리·균사를 결합한다. 모든 지역을 같은 붉은 점액으로 덮지 않고 감염 양상에 차이를 둔다.
- 쿼터뷰 가독성: 캐릭터 실루엣, 발밑 위치, 공격 범위, 상호작용 대상을 알아볼 수 있게 한다. 큰 건물의 가림 처리를 고려한다.
- 소리: 침묵, 건물의 울림, 호흡과 멀리서 겹치는 속삭임으로 불안을 만든다. 전투 신호와 서사적 속삭임을 구별한다.
- UI: 최소한의 상태·상호작용 안내부터 시작한다. 감염 연출이 정보 판독을 방해하지 않도록 한다.

## 8. 기술 구조와 코드 변경 예정

기존 문서상 프로젝트는 사각형 렌더링 기반 코드다. 아래는 구현 계획이며 이번 기획서 작성에서 소스를 재분석하거나 수정하지 않았다.

| 변경 위치 또는 추가 모듈 | 예정 내용 | 목적 |
|---|---|---|
| SimpleGame.cpp의 Idle·입력·렌더 콜백 | 시간 계산과 Game 업데이트 연결, 키 상태 전달, 갱신 요청 분리 | 게임 진행과 그리기 책임 분리 |
| Game.h/.cpp 추가 | Player·World·Camera의 초기화와 업데이트·그리기 연결 | 전체 흐름 관리 |
| Player 추가 | 위치·방향·이동과 후속 전투 상태 | 플레이어 기능 독립 |
| Camera·좌표 변환 추가 | 월드에서 화면으로 변환하고 추적 | 쿼터뷰 탐험 지원 |
| World·Chunk 추가 | 지형·오브젝트 구성과 주변 구역 관리 | 넓은 맵을 단계적으로 확장 |
| Renderer.h/.cpp·셰이더 | 선택한 에셋 방식에 맞는 지형·캐릭터 표현, 가림·화면 밖 제외 | 실시간 렌더링 확장 |
| 데이터 로더·리소스 관리자 추가 | 파일 검사·ID 참조 해석·이미지 등 공유 | 콘텐츠 제작과 코드 분리 |
| 퀘스트·저장 관리 추가 | 진행 조건·선택·월드 변경 상태 유지 | 분기와 재접속 상태 복원 |

초기에는 복잡한 비동기 스트리밍이나 범용 엔진을 만들지 않는다. 2D 에셋을 택하면 스프라이트와 그리기 순서를, 3D를 택하면 모델·변환 행렬·직교 카메라를 구체화한다.

이전 분석의 셰이더 실패 반환값, 상대 경로, 창 크기 변경, 자원 정리, Git 제외 파일 문제는 구현 전에 관련 코드를 확인해 필요한 범위에서 다룬다. 자동 수정 대상은 아니다.

## 9. 외부 데이터 파이프라인

제작 → JSON 등으로 저장 → 필수 값·형식·참조 검사 → 리소스 로딩 → 월드 인스턴스 생성 → 업데이트·렌더링.

| 데이터 | 포함할 정보 제안 |
|---|---|
| 타일 정의 | 타일 ID, 이미지·재질 참조, 통행 속성 |
| 맵·청크 배치 | 구역 좌표, 타일 배열, 오브젝트 배치 |
| 오브젝트 정의 | 종류 ID, 리소스, 충돌·상호작용 기본 속성 |
| 오브젝트 인스턴스 | 고유 ID, 종류 참조, 위치·높이, 개별 설정 |
| 스프라이트 메타데이터 | 이미지 경로, 프레임 영역, 표시 크기, 기준점, 애니메이션 |
| 퀘스트·대화 | 고유 ID, 조건, 진행 단계, 선택과 결과 |
| 세이브 | 위치·보유 자원·퀘스트 상태·열린 상자 등 원본에서 바뀐 상태 |

JSON은 초기 후보이며 구체적 파서와 스키마는 미정이다. 실제 이미지는 별도 파일에 저장한다. 원본 오브젝트 종류와 개별 배치를 분리하고, 세이브에는 안정적인 고유 ID를 사용한다. 누락·잘못된 참조는 진단 가능한 오류로 처리한다. 같은 리소스는 공유하여 중복 로딩을 줄인다.

## 10. 초기 제작 범위와 단계별 산출물

최신 사용자 요구에 따라 첫 제작 범위는 파괴된 마을의 5분 이내 튜토리얼이다. 상세 설계는 TUTORIAL_LEVEL.md를 따른다.

- WASD 이동, E 상호작용, 1/2 대화 선택, Esc 일시정지.
- 생존 인물은 주인공과 위독한 감염자 한 명이며 시체를 환경에 배치한다.
- 마지막 성혈 획득·전달과 짧은 선택 후 출구에서 종료한다.
- 쿼터뷰 폐허, 시체, 균사, 포자와 핏빛 강조로 실제 렌더링 분위기를 표현한다.
- 구현 순서: 이동·카메라·맵 → 상호작용·퀘스트 → 환경 연출.
- 전투·추가 NPC·디스크 저장·대형 월드 확장은 후속 범위다.
- 사용자 플레이로 진행 시간과 조작·선택·분위기를 확인한다. 현재 실측값은 없다.

## 11. 주요 위험과 대응

| 위험 | 대응 방향 |
|---|---|
| 오픈 월드와 다중 결말의 과도한 범위 | 첫 플레이 구간을 완성한 뒤 검증된 구조로 지역 확장 |
| 2D/3D 결정 지연 | 렌더러·에셋 파이프라인 확장 전에 결정 |
| 분기 조합 증가 | 고유 퀘스트 ID와 명시적 상태, 어느 선택으로도 주요 증표 확보 |
| 성혈의 서사와 플레이 충돌 | 비용·결과를 설명하고 필수 회복이 불공정한 벌이 되지 않도록 설계 |
| 코스믹 호러의 과잉 설명 | 관측 가능한 사실과 해석을 분리 |
| 월드 로딩·가림·렌더링 부담 | 구역 관리와 필요한 대상만 처리, 이후 사용자 측 측정으로 최적화 |
| 데이터 변경 후 세이브 불일치 | 안정적인 ID와 데이터·저장 버전 관리 검토 |

## 12. 우선 결정할 사항

1. 2D 이미지 기반인가 실제 3D 모델 기반인가: 렌더러와 자산 제작 경로를 결정한다.
2. WASD 이동과 E 상호작용은 확정 방향이다. 전투 기본 행동은 튜토리얼 이후 결정한다.
3. 성혈의 플레이 효과와 대가: 세계관이 실제 플레이에 어떻게 나타날지 정한다.
4. 인원·기간·자산 제작 방식: 첫 구현 범위와 이후 확장량을 조정한다.
5. 성혈 확산 경로·수백 년 잠복 원인·기근 해결 방식: 설정의 연결을 보완한다. 기존 제안은 아직 확정하지 않는다.

## 13. 개발 협업 원칙과 문서 관계

- 코드 변경 전 파일·함수·클래스의 어느 부분을 어떻게 바꾸는지, 목적과 예상 동작을 한국어로 보고한다. 코드 전체는 요청 시 제시한다.
- 설명 요청만으로 코드를 수정하지 않는다. 실제 변경 후 변경사항과 직접 확인할 항목을 보고한다.
- 기본적으로 빌드·실행·테스트·실행 결과 확인은 사용자가 담당한다. 예외가 필요하면 먼저 이유를 설명한다.
- 관련 파일부터 탐색하고 불필요한 리팩터링을 피한다. 기존 사용자 변경을 보존한다. 커밋·푸시는 요청 시 수행한다.
- AGENTS.md는 작업 지침, GAME_DESIGN.md는 세계관·퀘스트 기준, 이 문서는 전체 초기 기획의 종합본이다. 사용자 결정이 바뀌면 관련 문서를 함께 갱신한다.
- 이 문서와 INITIAL_GAME_PLAN.txt는 동일 내용으로 제공한다. 기존 기획이나 소스 구현을 자동으로 변경하지 않는다.

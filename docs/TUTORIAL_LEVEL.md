# 튜토리얼 프로토타입 — 마지막 이름

상태: 사용자 요구에 따른 레벨 설계안. 구현·실행 결과물이 아님.

## 1. 목표와 범위
WASD로 이동하는 2.5D 쿼터뷰 게임의 첫 레벨이다. 파괴된 마을에서 시작하며, 살아 있는 인물은 주인공과 죽기 직전의 감염자 한 명뿐이다. 다수의 시체는 정적인 환경 오브젝트로 배치한다. 짧은 퀘스트를 통해 이동·상호작용과 성혈 의존, 인간성, 군집의 공포를 경험한다.

의도된 첫 플레이는 3분 30초~4분 30초, 설계 예산은 4분 40초다. 멈추거나 무한히 배회하는 시간까지 5분으로 강제 제한하지 않는다. 실제 소요 시간은 사용자 플레이로 확인해야 한다. NPC는 서사상 위독하지만 실시간 사망 타이머는 두지 않는다.

이 프로토타입에는 전투·추가 생존자·적 출현·인벤토리 화면·성장·전체 월드 스트리밍을 넣지 않는다. 전투는 본편의 후속 설계 범위다. 작은 독립 구역이지만 본편 오픈 월드의 서막으로 연결한다.

## 2. 조작
| 키 | 동작 |
|---|---|
| W/A/S/D | 화면 기준 위/왼쪽/아래/오른쪽 이동 |
| E | 가까운 대상 조사·대화·획득·퀘스트 물품 전달, 대사 다음 줄 |
| 1 / 2 | 최종 대화 선택지 결정 |
| Esc | 일시정지와 조작 안내 |

쿼터뷰 월드의 축과 화면 이동 방향은 변환한다. 대각선은 정규화하여 속도를 일정하게 한다. E는 눌린 순간 한 번만 처리하며, 대사 창이 열린 동안 이동과 월드 상호작용을 막는다. 범위 안에서 가장 가까운 유효 대상 하나를 강조하고 ‘E 대화’처럼 동작을 표시한다. 벽 너머 대상은 선택하지 않는다. 범위 초기값은 월드 1.5단위로 제안한다.

## 3. 배치와 이동 동선
초기 크기 제안은 28×22 월드 단위다. 좌표는 월드 평면 기준이며 화면 좌표와 구분한다. 실제 충돌 구간과 카메라 구도에 맞춰 조정한다.

| 지점 | 좌표 제안 | 구성 |
|---|---|---|
| A 시작 | (4, 3) | 무너진 마을 입구, 플레이어, WASD 안내 |
| B 광장 | (12, 10) | 붕괴한 우물, 기대앉은 감염자, 붉은 작은 등불 |
| C 약제소 잔해 | (21, 15) | 지붕 없는 건물, 열린 구급함과 마지막 성혈 한 병 |
| D 출구 | (24, 20) | 무너진 성문 사이의 통로, 성도를 향한 길 |

필수 동선: A → B → C → B → D. 꺾인 길을 포함해 60~75단위 이내, 이동 속도 초기값 3단위/초. 순수 이동은 약 20~25초이며 나머지는 관찰·조작 학습·대사·연출에 배분한다. 거리만으로 플레이 시간을 늘리지 않는다.

잔해로 바깥 경계를 막되 길은 캐릭터 두 명 이상 폭을 확보한다. 시체 8~12구를 입구·광장·약제소에 분산하고 필수 통로는 막지 않는다. 대부분 비상호작용 장식이며 1구만 짧은 조사 문구를 제공한다. 광장의 등불과 약제소 표식을 한 동선에서 볼 수 있게 배치한다. NPC 뒤 높은 구조물과 전면 벽은 낮추거나 투명화하여 캐릭터를 가리지 않는다.

## 4. 퀘스트 — 마지막 이름
감염자 가칭 ‘에른’은 마지막 성혈을 가져와 달라고 부탁한다. 목표는 완치가 아니라 잠시 자신의 이름과 의지를 유지하는 것이다.

| 예상 구간 | 진행과 학습 |
|---|---|
| 0:00~0:30 | 마을 입구에서 시작. 어두운 폐허와 시체, WASD 이동 학습. 긴 도입 영상 없음. |
| 0:30~1:10 | 광장의 감염자에게 E로 대화. ‘약제소에서 마지막 성혈을 찾아라’ 수락. |
| 1:10~2:10 | 잔해 사이 짧은 탐색. 약제소 구급함에 E를 눌러 성혈 획득. 선택적 시체 조사 10초 안팎. |
| 2:10~3:00 | 감염자에게 돌아가 E로 투여. 호흡은 안정되지만 손끝에서 균사가 자라남. 치료와 감염의 양면성 전달. |
| 3:00~3:45 | NPC가 성도 통행패와 단서를 건네고 이름을 기억해 달라고 함. 1 ‘당신의 이름을 기억하겠다’ / 2 ‘당신이 본 것을 말해 달라’. |
| 3:45~4:20 | 연결된 속삭임과 환경 반응. 퀘스트 완료, 출구로 이동. |
| 4:20~4:40 | 본편 연결 문구와 프로토타입 완료 표시. |

대사는 전체 8~10개의 짧은 줄을 목표로 하고 E로 넘긴다. 위 시간은 설계 가정이며 측정값이 아니다. 대화 스킵은 가능하고, 선택에 제한 시간은 없다.

핵심 대사 초안:
- 첫 만남: ‘약제소에… 마지막 한 병이 있어. 낫게 해 달라는 게 아니야. 잠깐만, 나로 있게 해 줘.’
- 투여 후: ‘숨은 돌아왔는데… 안에서 다른 것이 깨어나.’
- 공통 단서: ‘성도로 가. 그들은 아직 이것을 기적이라 불러.’
- 선택 1 이후: ‘에른. 내 이름은 에른이야.’ 이름을 기억한 플래그 저장.
- 선택 2 이후: ‘우리가 듣는 게 아니야. 저쪽에서… 우리를 듣고 있어.’ 증언을 들은 플래그 저장. 이는 NPC의 해석이며 우주의 진실로 확정하지 않는다.

두 선택 모두 퀘스트와 출구 진행을 허용한다. 선택으로 본편 엔딩을 즉시 고정하지 않는다. NPC는 마지막에 자아를 잃은 듯 움직임을 멈추지만 적으로 변하지 않는다. 죽었는지 군집에 흡수됐는지는 단정하지 않는다.

## 5. 코스믹 호러와 렌더링 결과물 요구
최종 프로토타입은 실제 게임 화면에서 분위기가 드러나야 한다. 설계 문서나 콘셉트 이미지만으로 렌더링 완료라고 처리하지 않는다. 현재는 에셋 방식 미정이므로 아래 시각 조건을 구현 목표로 둔다.

- 고정 쿼터뷰 각도와 부드러운 플레이어 추적. 작은 맵 경계에서 카메라를 제한한다.
- 청회색 폐허와 회백색 균사, 성혈·등불의 핏빛 발광을 대비한다. 통로와 플레이어 발밑은 읽을 수 있게 유지한다.
- 파괴된 지붕·벽·우물·마차, 누운 시체와 약제소 구급함을 실루엣으로 구분한다. 회색 사각형만 있는 블록아웃은 분위기 결과물 완료가 아니다.
- 바닥 어둠과 접지 그림자로 깊이를 표현한다. 낮은 농도의 안개와 느리게 떠다니는 포자를 겹치되 길과 UI를 가리지 않는다.
- 성혈 투여 순간 NPC 손의 균사가 밝아지고, 떨어진 여러 균사 군락이 같은 박자로 반응한다. 시체가 살아나거나 새 인물이 나타나지 않는다.
- 속삭임은 좌우 또는 여러 방향에 겹친다. 소리가 없는 상태에서도 포자의 동시 움직임과 짧은 자막으로 사건을 인지할 수 있게 한다.

사용자 확인용 대표 구도: ① 입구에서 폐허·시체·광장의 붉은 등불이 함께 보이는 화면 ② NPC 투여 후 주변 균사가 반응하는 화면. 실제 캡처와 플레이 확인은 사용자가 수행한다.

## 6. 구현 시 변경 위치와 책임
| 위치·모듈 | 수정 또는 추가 예정 |
|---|---|
| SimpleGame.cpp | WASD 누름·해제 전달, 시간 기반 Idle 업데이트, E·숫자·Esc 입력 전달 |
| Game / Player / Camera | 플레이 상태·이동·충돌·추적, 대화 중 이동 정지와 일시정지 |
| Renderer와 셰이더 | 쿼터뷰 환경·인물·시체, 가림 순서, 색조·포자·안개·발광 표현 |
| InteractionSystem | 거리·벽·대상 우선순위 검사와 E 프롬프트 |
| Dialogue / TutorialQuest | 대사·선택과 단계 전환, 중복 지급·반복 투여 방지 |
| 데이터 로더 / ResourceManager | 맵·배치·스프라이트 참조 읽기와 공유 리소스 관리 |
| UI | 이동 안내, 현재 목표 한 줄, 상호작용 안내, 선택지, 완료 표시 |

JSON 파일 제안: tutorial_village.json(지형·배치·충돌), tutorial_objects.json(종류·리소스), tutorial_dialogue.json(대사), tutorial_quest.json(조건·단계). 실제 에셋은 별도 파일로 둔다.

진행 상태: NotStarted → NeedBlood → HaveBlood → Administered → ChoiceMade → ExitReady → Completed.
플래그: bloodCollected, bloodAdministered, rememberedName, heardTestimony, tokenGranted.
구급함을 먼저 조사해도 획득을 보존하고 첫 대화 후 HaveBlood로 연결한다. 재조사·재대화는 물품과 보상을 중복 생성하지 않는다. 출구는 완료 전 ‘그 사람을 두고 떠날 수 없다’ 등 짧은 안내로 처리한다. 이동 중 시간을 보내도 NPC가 먼저 사망하여 막히지 않는다. 첫 프로토타입은 세션 상태를 우선하며 디스크 저장은 후속 구현 범위다.

## 7. 제작 순서와 사용자 확인 항목
1. 맵·이동·카메라·충돌: A-B-C-B-D 동선 확보.
2. 상호작용·대사·퀘스트: 획득·전달·선택·종료까지 연결.
3. 환경 에셋·색조·포자·투여 반응: 요구된 분위기 화면 완성.
4. 사용자 플레이 확인: 첫 진행 5분 이내, 두 선택 모두 완료, 선획득·재대화 정상, 살아 있는 추가 인물 없음, WASD 방향과 가림 가독성 확인.

에셋 표현은 구현 착수 전에 2D 스프라이트/실제 3D 중 결정할 사항이다. 레벨 동선과 퀘스트 구조는 어느 방식에도 적용한다. Codex는 사용자 지침에 따라 빌드·실행·테스트를 기본적으로 수행하지 않는다.

## 구현 현황 추가
설계 후 실제 코드와 배치 데이터를 추가했다. 구현 범위·실행 방법·설계 대비 제한은 PROTOTYPE_IMPLEMENTATION.md를 따른다. 아직 빌드와 플레이는 확인하지 않았다.

## 최신 시각 개선과 맵 확장
이 항목은 위 초기 좌표·영문 UI·렌더링 계획보다 우선한다.
- 맵: 52×40. 시작 (8,7), 감염자 (19,17), 성혈 (33,22), 출구 (43,32).
- 남문·광장·예배당·약제소·묘역·동쪽 길을 구분하고 선택 조사 지점 세 곳을 추가했다.
- 필수 퀘스트는 동일하며 5분 이내 목표를 유지한다. 확대된 동선의 실제 시간은 사용자 확인이 필요하다.
- 한국어 UI·외부 대사, 재질 셰이더·MSAA·FXAA·블룸·후처리, 환경 종류별 형태, 분절형 캐릭터 애니메이션을 구현했다.
- 실제 구현 범위와 제한은 PROTOTYPE_IMPLEMENTATION.md를 따른다.

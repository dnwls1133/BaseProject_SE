# Actor 기반 화면 구성

기준일: 2026-09-21. 사용자 요청에 따라 화면의 배치 객체를 Actor 기반으로 제어하도록 변경했다. 빌드·실행·테스트는 수행하지 않았으며 실제 동작 확인은 사용자 담당이다.

## 책임 구분

- **Actor**: 배치 객체의 공통 위치 x/y, 깊이 보정, 활성화·표시·제거 상태, 업데이트와 그리기 진입점.
- **Scene**: 이번 프레임에 그릴 Actor 참조를 모아 렌더링 단계와 앞뒤 순서를 관리한다.
- **Renderer**: Actor가 요청한 도형·글자·재질을 실제 OpenGL 호출로 그린다. 프레임버퍼·셰이더·후처리는 렌더링 자원과 처리 과정이므로 배치 Actor로 만들지 않는다.
- **Game / LevelOne**: Actor의 소유, 입력 전달, 퀘스트·전투 규칙, 카메라와 레벨 전환을 관리한다.
- **ModelCache**: 재사용할 모델 데이터다. 같은 모델을 사용하는 개별 캐릭터와 장식은 각각 별도의 Actor다.

화면 표현의 진입 경로는 `Game 또는 LevelOne → Scene → Actor::Render → OnRender → Renderer`이다. Actor 클래스를 추가하기만 한 것이 아니라 기존 직접 렌더링 순회를 이 경로로 교체했다.

## 변환한 객체

| 구간 | Actor 구성 |
|---|---|
| 튜토리얼 | Object가 Actor를 상속. NPC·벽·등불·상자·출구·잔해 등의 기존 맵 배치를 유지 |
| 튜토리얼 발자국 | Footprint가 Actor를 상속. 개별 위치와 수명을 유지 |
| 첫 전투 레벨 | Enemy·Drop·Prop·FloatingText가 Actor를 상속 |
| 두 구간의 플레이어 | CallbackActor. 위치는 player.x/y로 일원화하고 UpdatePlayer를 Actor 업데이트에 연결 |
| 지형 | 지형 전체를 하나의 CallbackActor로 묶어 타일·바닥 무늬를 그림 |
| 분위기 | 튜토리얼 포자·안개 등은 분위기 CallbackActor가 그림 |
| UI | 각 레벨의 HUD CallbackActor가 목표·메뉴·능력치 창·미니맵을 그림 |

CallbackActor도 Actor의 파생 클래스이며 공통 상태 검사를 거친다. 기존 Game·LevelOne·VillageArt의 표현 함수를 콜백으로 연결하여 그림의 모양과 게임 규칙을 재작성하지 않았다. 적 AI는 Enemy::OnUpdate에서 LevelOne::UpdateEnemy로 연결한다.

캐릭터를 구성하는 원·사각형, 화로에 붙은 불꽃, 적의 그림자·체력 막대, HUD의 개별 글자는 소속 Actor의 표현으로 묶는다. 지형 타일·안개 입자·UI 위젯을 각각 독립 Actor로 분리한 것은 아니다. 독립적으로 이동·생성·제거해야 하는 새 객체는 별도 Actor로 추가한다. 현재 지형·분위기·HUD는 기존 좌표계를 사용하는 고정된 묶음이며, 부모-자식 좌표 변환과 묶음 전체의 이동·회전·크기 변환은 추가하지 않았다.

## 공통 제어 규칙

- `SetPosition(x, y)`: 플레이어·적·맵 오브젝트·아이템 등 개별 월드 객체의 위치를 변경한다. 카메라와 월드 위치는 분리한다.
- `SetVisible(false)`: 렌더링만 숨긴다. 업데이트와 게임 판정은 유지한다. 적의 그림자·체력 막대·미니맵 표시, 등불의 빛도 원래 객체의 표시 여부를 따른다.
- `SetActive(false)`: 업데이트와 렌더링을 중단한다. 적의 공격 대상 판정, 아이템 획득, 튜토리얼 배치 객체의 충돌·상호작용에서도 활성 상태를 확인한다.
- `Destroy()`: 제거 상태로 표시하여 즉시 업데이트·렌더링 대상에서 제외한다. 획득한 아이템·수명이 끝난 피해 숫자·발자국은 업데이트의 정리 단계에서 컨테이너에서도 제거한다.
- 맵 배치 객체는 기존 퀘스트가 인덱스를 참조하므로 실행 중 임의로 배열을 압축하지 않는다. 제거 상태로 제외한 뒤 레벨을 다시 로딩할 때 정리한다. 장식·적도 맵 재생성 시 컨테이너를 정리한다.
- 적의 사망은 Destroy와 다르다. 사망한 적은 전투에서 빠지지만 시체를 그리기 위해 Actor를 유지한다.
- `Depth()`는 기본적으로 x + y + depthOffset을 반환한다. 필요한 파생 클래스에서 정렬 기준을 재정의할 수 있다.

첫 전투 레벨의 제단 상호작용과 맵 재생성 거리도 시작 좌표 상수 대신 살아 있는 제단 Actor의 위치를 참조하도록 변경했다. 제단을 비활성화하면 제단 상호작용에서 제외한다. 이동 불가 타일 자체의 충돌은 RandomLevelMap이 계속 담당한다.

## 렌더링 단계

1. Ground: 지형, 바닥 효과, 발자국, 바닥에 비치는 등불 빛.
2. Shadow: 객체 그림자, 적 공격 범위 예고.
3. World: Actor::Depth를 기준으로 안정 정렬한 캐릭터·건물·아이템.
4. Effects: 안개·포자·광원 효과.
5. 장면 후처리: 기존 MSAA 처리·블룸·FXAA·색보정.
6. Overlay: 적 체력 막대와 떠오르는 피해·경험치 숫자.
7. UI: HUD, 대화, 능력치와 일시정지 화면.

각 Actor는 자신에게 필요한 단계에서만 그린다. 같은 깊이의 객체는 등록 순서를 유지한다. UI는 월드 정렬에 영향을 받지 않으며, 후처리 뒤에 그려 문자 선명도를 유지한다. Actor 사이에는 기본 재질 상태를 복원한다.

## 소유와 수명

Actor의 실제 소유자는 각 레벨의 멤버와 타입별 vector다. Scene은 Render 호출 안에서 만들어지는 비소유 참조 목록이며 프레임 간 포인터를 보관하지 않는다. 따라서 아이템 추가·맵 재생성으로 vector가 재할당되어도 이전 프레임의 주소가 남지 않는다.

렌더링 중에는 Actor 컨테이너를 추가·삭제하지 않는다. 생성·제거는 입력 또는 업데이트 단계에서 수행하고 그 다음 Render에서 목록을 새로 만든다. Scene은 렌더링만 담당하므로 공격·아이템 생성과 업데이트 순서는 레벨이 유지한다. 자신을 콜백으로 참조하는 Game과 LevelOne의 복사는 금지했다.

## 새 객체 추가 방식

Actor를 상속한 새 타입에서 필요한 상태를 선언하고 OnUpdate와 OnRender를 구현한다. 기존 레벨 컨테이너가 소유하게 한 뒤 레벨 업데이트에서 Actor::Update를 호출하고, Render에서 Scene::Add로 등록한다. 활성·표시 검사를 우회하도록 OnRender를 직접 호출하지 않는다.

개별 도형 호출과 모델 캐시 사용은 OnRender 또는 그 내부 표현 함수에 둔다. 퀘스트 보상이나 전투 판정처럼 여러 객체를 연결하는 규칙은 레벨에서 관리해도 되며, 대상 Actor의 활성·제거 상태를 확인해야 한다. 현재 구조를 곧바로 대규모 ECS나 전체 엔진으로 확대하지 않는다.

## 사용자 확인 항목

1. 직접 빌드 후 튜토리얼에서 이동·상호작용·발자국과 건물 앞뒤 가림을 확인한다.
2. 첫 레벨의 공격·적 추적·체력 막대·피해 숫자·아이템 획득이 기존처럼 이어지는지 확인한다.
3. Tab·Esc 화면과 한국어 UI가 후처리 이후에 표시되는지 확인한다.
4. 제단 근처 E/R, 사망 재도전과 반복 맵 재생성 후 객체가 남거나 중복되지 않는지 확인한다.
5. 코드에서 개별 적/장식의 SetVisible·SetActive를 조절할 경우 몸체뿐 아니라 부속 효과와 판정도 위 규칙을 따르는지 확인한다.

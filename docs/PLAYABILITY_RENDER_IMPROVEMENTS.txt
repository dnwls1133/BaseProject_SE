# 대화·자율 사회·3D 렌더링 개선 — 2026-10-08

사용자가 요청한 순서대로 소스와 외부 데이터를 수정했다. 이 문서는 구현 범위를 기록한다. 빌드·실행·테스트·화면 확인·새 프로파일 측정은 수행하지 않았으며 사용자가 담당한다. 60 FPS 또는 시각 품질 개선 폭은 아직 확인되지 않았다.

## 1. 프레임 예약과 이동

- SimpleGame::Tick은 업데이트 종료 시점에 16ms를 다시 더하던 예약을 16.667ms 절대 주기로 변경했다. 누적 지연이 한 주기를 넘으면 예약을 보정하며 밀린 업데이트를 무제한 반복하지 않는다.
- WorldRenderer3D의 모든 glDrawArraysInstanced를 기존 draw_call_count/geometry_draw_count 집계에 포함했다. 이전 로그에는 이 호출이 누락되어 있었다. 새 draw call 숫자가 커져도 그것만으로 성능 악화라고 판단하지 않는다.
- SocietyCombat::MoveTo는 매번 전체 맵 부모 배열을 생성하는 BFS를 재사용 배열 기반 A*로 변경했다. 프레임당 최대 2회·총 2,048개 확장 노드, 탐색 중 약 1ms 간격 제한을 사용한다. 시간 제한은 32노드마다 확인하는 소프트 예산이다. 긴 경로에는 유효한 부분 경로를 반환해 이어 탐색한다. 도달 불가/예산 대기에는 재시도 지연을 두며 순간이동하지 않는다.
- NpcLife의 막힘 판단은 목표와의 최단 거리 기록 대신 실제 위치 변화로 판단한다. 정상적인 우회는 막힘으로 누적하지 않는다. 한 계획의 실패 로그 반복을 막았다.
- ReconcilePositions에서 작업 장소별 접근 가능한 서로 다른 예약 자리를 구성하고, 이동과 숙소 표현이 같은 자리를 사용한다. 콘텐츠 오류를 숨기는 대체 맵은 생성하지 않는다.

## 2. 대화와 UI

- WorldSociety가 대화 상대/유효 시간을 관리하고 LevelOneSociety가 한 개 창에 NPC 응답과 최대 3개의 선택지를 표시한다. 직책, 부상, 실제 요청, 증거 보유 여부에 따라 화제가 달라진다.
- F로 대화, 1~3으로 화제 선택, 거래·치료·가입·지원 등은 NPC의 조건을 읽고 1 실행/2 보류. 실제 실행 시 Interact가 현재 자원과 조건을 다시 검사한다. 결과는 같은 대화창에 남으며 HUD에 중복 표시하지 않는다.
- [ / ]는 다른 화제, 긴 응답은 U/O로 넘긴다. F/0/Esc로 닫는다. J의 세계 기록도 고정 18px 글자와 28px 행간으로 페이지를 나눈다. 글자 폭 측정은 실제 GDI 글꼴 메트릭을 사용한다.
- 대화 상대는 최대 45초 동안 플레이어를 바라본다. 다른 주민/세계는 계속 진행하며 위협·피격·사망·거리·군사 명령·기존 약속에 따라 대화를 거부하거나 끝낸다. 저장/불러오기/월드 교체 시 임시 대화 상태를 해제한다.
- 근처 모든 주민의 긴 대사를 동시에 띄우지 않는다. 가장 가까운 대화 후보 또는 선택한 인물만 이름/소속을 표시하며, 교전 중 주민의 체력 막대는 유지한다. 상세 계획과 사건은 J에 둔다.
- Renderer의 문자열 캐시는 일괄 삭제 대신 최근 사용이 적은 항목부터 정리한다(최대 512항목, 약 32MiB 기준). 글꼴 객체를 재사용하고 TextWidth는 텍스처 생성 없이 측정한다. 글리프 아틀라스는 아직 도입하지 않았다.

## 3. 주민 교역과 세력 전선

- NpcLife의 일터 선택에 직책·개인 목표·성향·기억한 서사 증거의 가중치를 반영한다. 배고픔·피로·기존 약속 등 선행 조건은 유지한다.
- 상인의 시장 운송은 도착 후 실제 수신자를 찾고 접근하여, 거리/시야와 상대 상태를 확인한 뒤 화물·공동 보급·개인 관계를 변경한다. 상대는 가까운 전달 중 잠시 마주 보고 기다린다. 수신자가 없으면 목적지 지역 창고에 화물을 인계한다. 운송 화물이 개인 식량으로만 쌓이던 경로를 수정했다.
- 전쟁 단계는 0 집결 → 1 전선 이동 → 2 현지 교전 → 3 방어선 이탈 확인 후 거점 진격이다. 병력 현황과 실제 위치로 단계가 변한다. 거점 점유·보급 부족·손실·협상은 기존 휴전/통제권 규칙과 연결한다. 선언/전투 승자/생존자는 고정하지 않는다.
- CampaignGoal은 명령 조회와 실제 이동 목표를 분리한다. CampaignOrder를 조회하는 과정이 진행 중 전투 대상을 지우지 않게 했다. 출정 병력은 실제 소지 식량을 먹어 포만감을 회복한다.
- 가까이 보이는 적과 자신을 공격하는 적을 우선 평가한다. 세력 교전 중인 병력은 가까운 몬스터 위협에 대응하며 멀리 있는 몬스터 때문에 항상 전선을 포기하지 않게 했다.
- 첫 맵은 기존 256×200, 주민 40명을 유지한다. 북부 피난지에서 이어지는 (60.5, 60.5)/(68.5, 69.5)에 정화 기사단·포자 공동체의 전초와 선발 병력을 배치하고 길을 추가했다. 전쟁의 거점 목표는 성혈의 습지다. 분쟁 전초는 시작 마을 자체와 구분된다.
- 연구회 상인 한 명은 초기 피난지 시장을 방문한 상태로 시작한다. 이후 거래/이동은 욕구와 규칙에 따른다. 국경 교역로의 초기 몬스터 배치를 3→1로 줄이고, 몬스터 최초 배치를 작업 장소에서 9타일 이상 떨어뜨렸다. 이후 이동/적대/생태 상호작용은 계속한다.

## 4. 3D 품질과 렌더 비용

- Pilgrim.mesh의 분절 갑옷, 어깨판, 후드 가장자리, 가죽끈, 겹망토, 성혈 병의 테두리와 검날을 보강했다. 다섯 세력의 장비 및 BloodChapel/UnionStorehouse/MyceliumSanctum/BloodObservatory/PurgeBastion에 구별되는 구조와 부속품을 추가했다. 기존 외부 모델/로더를 재사용한다.
- 재질 12(Metal)를 3D 로더와 셰이더에 추가했다. 금속과 유기체의 제한적인 반사, 거친 돌/목재/천의 구분, 화면 미분에 따른 무늬 필터링을 적용했다. 외부 PBR 텍스처나 외부 리깅 에셋을 추가한 것은 아니다.
- 구체 면 방향과 원통 측면 법선을 수정하고 후면 컬링을 켰다. 그림자 위치를 텍셀에 맞춰 정렬하고 하드웨어 비교 필터를 이용하는 4회 샘플 그림자로 바꿨다. MSAA·FXAA·블룸은 유지한다.
- 동적 인스턴스를 그림자 대상/제외 대상으로 나누어 불꽃·물·안개·발광·반투명 가림체는 그림자 정점 제출에서 제외한다. 혼합 재질의 지형 청크는 기존처럼 그림자 패스에도 제출하며 셰이더에서 물을 제외한다.
- 지름 0.14월드 단위 미만의 구체에는 8삼각형 도형을 사용한다. 포자·작은 발광점·공격 표시가 대상이며 전체 캐릭터를 저해상도 모델로 바꾸는 LOD는 아니다.
- 가까운 점광원은 최대 8개, 영향 반경 밖 계산을 제한한다. Scene은 변경된 Actor/부모 변환의 월드 경계만 재구성하고 직교 카메라에서는 중심/반경으로 투영한다. 정적 소품은 배치 행렬을 한 번 구성하여 기존 인스턴스 배치에 재사용한다. 최종 인스턴스 배열은 여전히 매 프레임 GPU에 제출한다.

## 5. 데이터와 저장

`.society`에 다음 레코드를 추가했다. 기존 version 1 줄 형식을 사용한다.

```text
# 세력A 세력B 점령목표지역 A집결X A집결Y B집결X B집결Y
frontier purge spore marsh 60.5 60.5 68.5 69.5
```

세력/지역을 먼저 정의하며 중복 쌍·알 수 없는 ID·맵 밖 좌표·초기 목표 소유자를 검사한다. 접근 지점 보정이 8타일 안에 불가능하면 로딩을 거부한다. 장소/주민/경로는 기존 `.life`, 지형과 길은 `.world`, 모델은 `.mesh`에 둔다.

플레이 저장은 **save_schema 5**, 3D 모델 캐시는 **형식 3**이다. 저장은 캠페인 단계·단계 시작 시각·양측 집결 좌표를 추가한다. 3D 캐시 변경은 재질 해석 범위 확장에 따른 것으로, 이후 일반 모델 데이터 수정은 내용 해시로 갱신한다. 기존 2D 모델 캐시는 형식 4를 유지한다.

기존 스키마/콘텐츠 해시가 맞지 않는 저장은 자동 변환하거나 덮어쓰지 않는다. 복원 실패 시 자동 저장을 중단하는 보호 처리를 유지했다. **이전 진행을 보관하려면 실행 파일 옆 `Saves/world.save`와 `.bak`을 별도로 보관한 뒤 새 세계를 확인하고 K로 저장한다.** 이번 작업에서 사용자 저장·로그·빌드 산출물을 삭제/이동하지 않았다.

## 6. 사용자가 확인할 순서

1. 새 콘텐츠로 첫 레벨 진입. F 대화창에서 소식 → 거래 조건 → 확정/보류, 중복 창·텍스트 겹침·자원 변경 확인.
2. 피난지 시장 및 국경 교역로에서 NPC가 접근하고 마주 보고 물자를 전달하는지, J 7의 계획/식량과 맞는지 확인.
3. 피난지에서 분쟁 전초로 이동해 양측 이동·공격·피격·후퇴를 관찰. 대화를 하지 않아도 진행되고 화면 밖에서도 상태가 이어지는지 확인.
4. 플레이어/세력 장비, 건물, 그림자 떨림, 구체 표면, 물결·불꽃과 공격 예고의 가시성 확인.
5. 새 저장으로 운송/약속/캠페인 도중 K/L 후 화물 중복이나 잘못된 단계 복원이 없는지 확인.
6. 같은 구성·해상도·시드·관찰 동선으로 1~2분 프로파일을 수집해 프레임 p95/max와 아래 지표를 비교. 기존 로그와 새 draw call 수는 계측 범위가 다르다.

새 지표: npc_path_expanded_nodes, npc_path_budget_deferred_count, npc_path_unreachable_count, npc_path_partial_route_count, world_3d_shadow_instance_count, world_3d_small_lod_count, scene_3d_bounds_rebuild_count, static_model_cached_part_count. 이벤트 campaign_stage/campaign_ration/life_delivery_received는 행위자·대상·원인·세계 시각과 함께 기존 Record 경로에 남는다.

GPU는 gpu_shadow_ms와 gpu_world_ms(본 렌더)를 분리했다. 이전 gpu_world_ms는 그림자를 포함했으므로 비교 시 새 두 구간을 함께 본다. 비동기 타임스탬프 경과 시간이며 GPU 이용률이 아니다. CPU 부모/자식 스코프와 GPU 시간을 중복 합산하지 않는다. 미회수 GPU 결과는 0으로 간주하지 않는다.

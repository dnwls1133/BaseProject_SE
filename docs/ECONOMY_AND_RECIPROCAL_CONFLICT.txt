# 실제 물류 경제와 상호 교전 — 2026-10-14

## 구현 범위

식량·약품·자재 3종을 지역 재고, 개인 소지금, 지역 금고와 연결했다. 소지금과 금고는 세력의 기존 군사 보급(supplies), 플레이어의 파편과 별개다. 식량은 WorldSimulation의 기존 식량 비율×100을 그대로 사용하며 약품은 기존 진료소 재고를 사용한다. 별도의 중복 식량 저장소는 만들지 않는다.

- 생산: NPC가 작업장에 도착해 실제 작업 시간을 채운다. 수요, 원재료, 수용량, 금고의 임금이 모두 있어야 생산한다. 원재료 소비 → 제품 증가 → 금고에서 개인에게 임금 지급이 이어진다. 작업 중 조건이 바뀌면 생산을 중단한다.
- 소비: 주민은 창고에서 개인 화폐로 실제 식량을 구매하고 식사로 소모한다. 돈과 식량이 모두 부족하면 유한 지역 재고에서 1인분 이하의 구호 배급을 받는다. 의료인은 현장에서 약품을 수령해 기존 대면 치료에 사용한다.
- 거래: 지역 부족분이 구매 주문을 만든다. 외부 경로를 따라 거리 지연 후 주문이 공개되고, 해당 출발 지역 또는 고향을 아는 운송자가 수락한다. 이동 거리·피로·운송료·성향을 평가한다. 모든 NPC가 먼 세계를 직접 관찰했다고 취급하지 않으며, 게시판 전달은 거리 지연으로 추상화한다.
- 물류: 주문 수락 때 출발 재고를 예약하고 구매 금고의 대금을 예치한다. 창고 도착 시 출고, 실제 이동, 목적지 시장 도착 시 입고가 일어난다. 도착 후에만 판매 금고와 운송자에게 대금·운송료가 지급된다. 품목당 운송량은 최대 3이다.
- 소비 지역은 목표 재고를 남기며, 해당 품목의 생산 지역은 목표의 60%를 비상 비축으로 남긴다. 부족한 두 지역이 같은 물건을 계속 사고파는 순환을 줄인다.
- 전쟁·경로 정체·기한 만료 시 예치금을 반환한다. 이미 출고한 물자는 운송자가 출발 창고로 반송한다. 사망이나 반송 실패 때 화물은 손실로 기록되며 창고에 순간 반환되지 않는다. 출고 후 손실은 판매 지역이 부담하고 구매자는 환불받는 초기 계약 규칙이다.
- 선착장 자리가 없으면 대기하고 자리가 나면 이동한다. 기다리는 계약도 저장한다. 전투는 운송보다 우선하며, 살아남은 운송자의 미완료 계약은 유지한다.

기존 시간당 식량 자동 감소는 level1.sim에서 0으로 변경했다. 주민 식사·생산·전쟁·서사 사건의 실제 자원 변화는 유지한다. 균사 식량 사건도 남아 있으므로 완전히 폐쇄된 경제를 구현한 것은 아니다.

## 외부 데이터

SimpleGame/Data/Simulation/level1.society의 `economy Simulation/level1.economy`가 선택한다. 파일은 JSON이 아닌 UTF-8 version 1 줄 단위 형식이다.

- rules: 판단 주기(세계 분), 계약 기한(세계 분), 최대 운송량, 기본 운송료, 초기 개인 화폐, 식량·약품·자재 기본 가격.
- market: 지역 ID, 창고 ID, 시장 ID, 진료소 ID, 초기 금고, 초기 자재, 식량·약품·자재 목표 재고.
- recipe: 작업장 ID, 생산 품목(0 식량/1 약품/2 자재), 투입 품목, 투입량, 생산량, 작업 시간(실제 초), 임금.

북부 피난지·습지·묘역은 식량, 교역로·대성당·붉은 들판은 약품, 기사단 전초·균사 지대·얕은 물가는 자재 생산에 특화한다. 생활 장소·모델·Actor를 재사용한다. 기존 교역 경로의 역방향과 생산지 연결을 추가했으며 적대 관계에서는 계약하지 않는다. 데이터 변경 후 재시작해야 한다.

## 상호 전투

SocietyCombat::Damage에서 살아 있는 피격자가 실제 공격자를 즉시 대상으로 잡는다. 체력이 낮으면 후퇴하고 그렇지 않으면 반격한다. SocietyAI::Decide는 자신 또는 주변 아군을 공격하는 적을 인지하며, 직접적인 위협을 확인한 동안 비전투 행동을 선택하지 않는다. 경비는 아군 보호를 전투 판단에 반영한다.

SocietyWar의 전선에서 방어 측 병력 2명 이상이 남고 공격 측이 이탈하면 방어군이 공격 측 거점으로 진격하는 stage 4를 추가했다. 점령 판정·표시·저장도 이 단계를 지원한다. 실제 병력·체력·보급과 기존 휴전 조건은 유지하며 승패나 전쟁 지속을 보장하지 않는다.

## 화면과 관측

- NPC가 운반하는 화물: 식량 황토색, 약품 붉은색, 자재 회청색. 전투로 운반 자세가 바뀌어도 실제 화물은 표시한다.
- 창고/시장 주변 물자 더미: 같은 지역 재고를 요약 표시한다. 두 개의 별도 인벤토리가 아니다. 품목별 최대 4더미로 제한하고 기존 Actor와 3D 인스턴스 제출 경로를 사용한다.
- 작업장 근처 이름 아래 진행 막대: 실제 작업 누적 시간 기준이다.
- HTML 모니터: 경제 지역별 현재/목표 재고, 가격, 금고, 생산·수입·수출 누계, 주문 단계·운송자·예치금·운송료, NPC 소지금·계약 ID. 기존 schema_version 1에 선택 필드를 확장했다.

## 저장과 프로파일

게임 저장 schema는 6이다. 금고·자재·가격·누계·소지금·진행 계약·예치금·작업 재선택 시각을 안정적인 지역/NPC/장소 ID로 저장한다. 복원 시 계약 ID, 화물, 장소, 행동 단계, 예치금 및 중복 레코드를 검사한다. 식량과 약품은 기존 저장 경로를 재사용한다. 완료 계약 목록은 제한된 실행 중 이력이며 재실행에는 진행 계약과 누계가 이어진다.

schema 5 이하 저장은 자동 변환하지 않는다. 기존 world.save와 .bak를 삭제하거나 수정하지 않았다. 구 저장 불일치 시 기존 자동 저장 중단 정책을 유지한다. 새 경제 상태로 수동 저장하기 전 사용자가 기존 저장을 별도로 보관해야 한다.

cpu_economy_decision_ms, cpu_economy_production_ms, cpu_economy_transfer_ms, economy_active_order_count, economy_delivery_count를 기존 JSONL에 추가했다. society_change에는 주문·예약·출고·반송·손실·생산·구매·정산과 원인 ID를 남긴다. 경제 주문/이력은 최대 64개이고 판단은 설정된 세계 분 주기로 처리한다.

## 사용자가 확인할 항목

1. 새 데이터로 시작한 뒤 NPC가 창고를 방문해 화물을 들고 다른 지역으로 이동하는지 확인한다.
2. 출고 때 출발 재고만 줄고, 납품 때 목적지 재고와 판매 금고·운송자 소지금이 증가하는지 모니터에서 비교한다.
3. 재료가 부족하거나 제품 목표가 충족된 작업장은 생산을 멈추는지 확인한다.
4. 교전 중 양측의 실제 체력·명중·누적 피해가 바뀌는지 확인한다. 방어군 반격은 전선의 실제 우세 조건이 충족될 때 발생한다.
5. 운송 중 저장/복원과 창고 자리 대기 중 저장/복원 후 화물·예치금이 이어지는지 확인한다.

이번 변경은 소스·데이터 구현이며 빌드·실행·테스트·화면 및 성능 측정은 수행하지 않았다. 범용 계획 탐색(GOAP), 자유 자연어 대화, 임의 세금·신용·채무 시장까지 구현한 것은 아니다. 다음 개선은 실제 모니터 기록을 바탕으로 운송 성공률, 장기 금고 고갈, 특정 일자리 쏠림, 경로 정체부터 조정한다.

# 다섯 마을·야외 개체군·소식 운반 — 2026-10-21

## 현재 구성
- 맵은 256×256이다. 두 세력을 유지한다.
- 기사단 피난 마을(refuge), 보급 교역촌(pilgrimage), 정화 요새(graves),
  정화 수도원(cathedral), 군체 심장림(growth)을 마을/거점으로 명시했다.
- 각 거점의 초기 거주자는 20명, 총 NPC 100명이다. 기사단 80명과 군체 20개체이며
  군체 거점은 사람의 시장·경제 활동을 하지 않는다. 그 외 4개 지역은 야외 지역이다.
- 인접 거점 중심 간 거리는 약 74타일이다. 플레이어 평상시 속도 3.7타일/초로
  장애물·전투 없이 중심 사이를 이동하면 약 20초를 목표로 한다.
  모든 거점 조합이 20초라는 의미는 아니다. 실제 도보 시간은 사용자 확인 전이다.
- 야외 몬스터는 NPC 100명과 별도로 100마리다. 인접 마을 연결 도로 주변 24타일
  이내 지형에서 배치하되 마을 반경+4타일 안쪽은 제외한다.
- 죽은 야외 몬스터는 기본 4초 뒤 이전 사망 위치에서 12타일 이상, 플레이어에서
  18타일 이상 떨어진 유효 지점에 재생성한다. 같은 Actor/컨테이너 슬롯을 재사용한다.
  안전한 지점을 찾지 못하면 1초 후 재시도하며 한 프레임 최대 4마리 처리한다.

## 외부 정의
Data/Levels/level1.world의 기존 version 1 레코드에 다음 항목을 추가했다.

```
village 지역ID 마을반경 초기거주인원
wilderness 목표개체수 재생성초 이전위치최소거리 플레이어최소거리 종류수 적ID...
```

village는 먼저 선언된 region을 참조한다. 로더는 중복·범위·적 참조와 사회 데이터의
초기 거주 인원 일치를 검사한다. 야외 후보 지형과 초기 100개 위치는 기존 Scene을
교체하기 전에 마련하며, 공간이 부족하면 콘텐츠 오류로 보고한다.

NPC, 생활 시설, 초기 오염도 함께 새 좌표로 옮겼다. 모델·지형·Scene·캐시 로더를
재사용했으며 새 레벨 클래스나 개별 NPC 클래스를 복제하지 않았다.

## 실제 이동에 의한 소식 전달
- level1.society의 `courier NPC_ID 정차수 지역ID...`로 순회 경로를 정의한다.
- 기사단의 네 마을에 각 2명, 총 8명의 전령을 배치했다. 전령은 정의된 우호 거점을
  실제 경로로 이동하고 가까운 현지 NPC에 접근해 정보를 공유한다.
- 일반 주민과 물자를 운송하는 NPC도 실제 관찰한 지역 정보를 들고 이동할 수 있다.
- Send/Deliver는 2.5타일 이내 대면·시야·생존·우호 소속을 검사한다. 거리별 시간이
  지났다는 이유만으로 원격 수신자에게 정보를 넣지 않는다. 출발자·전령 사망이나
  만남 실패는 전달을 성립시키지 않는다.
- 정보의 관찰 시각을 보존하므로 전달할 때마다 오래된 소식의 유효기간이 새로
  시작되지 않는다. 근접 조회·메시지 예산·분산된 갱신으로 전수 비교를 제한한다.
- 현재 첫 맵에서 참조하지 않는 기존 서사 보고 경로에도 대면 조건을 적용했다.
- 거래 주문의 운송자 선정도 구매 담당자 근처에서만 가능하다. 주문·지역 재고의
  시뮬레이션 상태와 NPC가 알고 있는 지역 정보는 구분한다.
- 전령은 별도 순회 역할이며 일반 생활·경제 작업에 동시에 배정되지 않는다.

## 통계와 관측
기존 로컬 HTML과 JSON regions 항목에 다음을 추가했다.
- is_village, resident_target, resident_total, resident_alive
- mood.label, score_ratio, fear_ratio, health_ratio, food_ratio, survival_ratio
- mood.wounded_residents, hungry_residents, nearby_hostiles

분위기는 기사단의 식량·건강·치안·공포·감염과 군체의 피복률·생존·위협을 반영한
읽기 전용 통계다. "안정된 생활", "긴장 속 생존", "굶주림", "전투 공포",
"군체 확장", "군체 소각 위협", "거점 붕괴" 등으로 표시한다.
거주 인원은 home ID, 현지 NPC 수는 현재 region ID 기준이므로 서로 다를 수 있다.
NPC에는 is_courier/courier_destination, 몬스터에는 wilderness/respawn_remaining_seconds,
전체 통계에는 village_total과 news_transport=physical_npc_contact를 추가했다.

추가 프로파일 키는 cpu_wilderness_respawn_ms, wilderness_respawn_count,
cpu_npc_news_contact_ms, cpu_npc_courier_motion_ms,
npc_physical_news_delivered_count이다. 전달·도착·재생성의 실제 사건도 기록한다.

## 저장과 확인 범위
저장 스키마는 9이다. 전령의 정차 위치·대기 상태, 소식의 관찰 시각, 몬스터의 남은
재생성 시간·개체군 구분·재생성 난수 상태를 보존한다. 이전 저장과 콘텐츠 서명은
호환되지 않으며 기존 파일을 임의로 삭제하지 않았다.

사용자의 기본 지침에 따라 빌드·실행·테스트·화면·시간·성능 측정은 수행하지 않았다.
사용자는 새 실행에서 5거점/초기 NPC 100/야외 몬스터 100, 이동 시간, 사망 후 다른
지점의 재생성, 전령의 실제 접근 전후 지식 변화, 마을 분위기 수치와 저장 복원을
확인해야 한다. NPC는 일반 세계 규칙에 따라 사망할 수 있고 주민 자동 증원은 추가하지 않았다.
